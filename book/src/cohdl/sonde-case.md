# 用 CoHDL 描述并检查 Sonde

> **定位**：用刚刚看过的整板检验语言：连接能否表达、复用后是否相同、检查能否发现错误、build 还缺什么。前置：[Sonde 整板解读](../course/01-sonde-circuit.md)。以下使用当前 CoHDL 0.6.0 已实现的语法；硬件功能未实测。

第一次读 CoHDL，可以先看[连接模型](connections.md)；本页第一遍只跟 R1 的实例和两个 net，`fn` 与 build 结果留到第二遍。

本次将 Sonde 的 **25 个元件全部写成 CoHDL 实例**，而不是只画一个功能框图。实际 `check` 通过；将展开后的连接与 KiCad 导出逐项比较，也得到相同的 **26 个连接分区、92 个已连接端点和 16 个 NC 端点**。

这说明 CoHDL 已经能忠实表达这块板的静态连接。下一步仍需区分两件事：图中没有提供完整采购料号；三态门、电源压降和协议时序也不是一张静态连接表能够模拟的行为。

**运行结果先看这里：整板 `check` 通过；整板 `build` 因 25 个缺物料绑定的 E801 停止。另一个只有两只真实贴片阻容的独立例子构建成功。** 下面先读实际源码，再看命令和错误对照。

## 把元件和引脚写成语言

完整模型位于仓库 `book/examples/sonde/sonde.cohdl`。例如电阻声明规定两个引脚及带单位的阻值：

```text

```

这只 R1 在完整 `design Sonde` 中的实际声明是：

```text
{{#include ../../examples/sonde/sonde.cohdl:r1_instance}}
```

`device` 是器件类型，`inst R1: AxialResistor<100ohm>` 才是板上的那一只电阻。`R1.A` 映射实物 1 脚，`R1.B` 映射 2 脚。`#[designator("R1")]` 保留原位号，方便在原理图和 PCB 上找到同一个对象。

模型同样声明两个完整的 `Quad74LS125` 实例，包含每颗芯片的 14 个脚。原理图的 U1A/U1B 是同一 U1 的不同门单元；CoHDL 把两组 E/D/O pin 放在同一个 U1 实例里，不能将它们编译成两颗独立芯片。

下表对照的是现有 KiCad 板：本例恰好一个物理 pin 对应一枚 pad，由独立验证器核对编号与网络。全板模型没有 part/footprint 绑定；这些 pad 不是本次 CoHDL build 生成或验证过的封装几何。

| 源码里的名称 | 原理图对象 | 现有 KiCad 板上的对应焊盘 |
| --- | --- | --- |
| `R1.A` / `R1.B` | R1 两端 | R1 焊盘 1 / 2 |
| `U1.D2` / `U1.O2` | U1B 输入 / 输出 | U1 焊盘 5 / 6 |
| `U1.E2` | U1B 使能 | U1 焊盘 4 |
| `J1.P2` | J1 的第 2 针 | J1 焊盘 2 |

这里的 `D2` 是芯片内第二个数据输入的逻辑名称；点号前面的 `U1` 指明所属芯片。它与板上位号叫 D2 的二极管是两个不同对象。

## net 表达铜连接，器件表达中间的关系

供电与 R1/D1 支路使用下面的实际源码：

```text
{{#include ../../examples/sonde/sonde.cohdl:power_nets}}
```

`net SENSE_DIODE: D1.Cathode, R1.A` 表示 D1 的阴极脚和 R1 的 1 脚在同一个电气网络上。R1 的另一脚出现在另一个 net 中：**电阻两端不是同一段铜**，两边通过实物电阻关联。

同理，D2 两侧分别是 `TARGET_POWER` 与 `VCC`。它们通过二极管供电，但 CoHDL 不会仅从器件名推算导通压降。模型保留两个网络，没有擅自把 VCC 标成实测的 3.3 V 或 5 V。

NC 用 `nc:` 明确列出。KiCad 导出将这些端点列成 16 个 `unconnected-*` 单点网络；CoHDL 在 IR 中单独记录 NC，因此验证器比较的是 **26 个连接分区加 NC 集合**，没有要求两种格式的“网络总条数”表面相等。

## 实际执行：检查、对照、编译

在仓库根目录运行：

```sh
cargo run -- check book/examples/sonde/sonde.cohdl --no-std --json
python3 book/examples/sonde/verify.py
cargo run -- build book/examples/sonde/sonde.cohdl --no-std --json
```

`--no-std` 只用于这份自包含的旧图连接模型。它没有依赖真实元件包；对照构建使用 manifest 与锁文件管理实际依赖。

验证器分别读取 KiCad 导出的 S 表达式网表与真正编译器检查后的 IR，比较位号、器件类型、阻容数值、物理脚全集、连接分区和 NC。IR 读取由示例目录里的独立 Rust 小程序完成，未修改编译器，也没有跳过物料绑定去伪装生产输出。

| 实验 | 实际结果 | 结论 |
| --- | --- | --- |
| 全板 `check` | 退出 0，零诊断 | 当前类型、连接义务与残余 DRC 通过 |
| KiCad 导出 ↔ 检查后 IR | 25 个元件、26 个连接分区匹配；108 个物理 pin 编号与既有板的 108 个 pad 一一对应 | 模型与参考的静态连接及数值一致，不含封装几何验证 |
| 全板 `build` | 退出 1，**25 个 E801** | 全部实例尚无 part 绑定；没有生成原板生产网表/BOM |
| 独立 RC 对照 `build` | 退出 0，生成 `.net`、BOM、封装文件 | 展示真实 part 绑定后的输出流程，范围仅两只贴片元件 |
| 同一 RC 对照重复构建 | 输出文件字节相同 | 该例子的重复构建稳定 |

E801 中的一条实际信息是：

```text
`Sonde::J1` (device `sonde::DB25`) has no part binding — the netlist/BOM would lie about what to buy
```

这是本次尝试完整编译后得到的真实停止点。网表能说明怎么连接，生产 BOM 还需要说明买什么；没有给连接器编造料号来消除错误。

成功构建的对照项目位于 `book/examples/sonde/rc-control/`：使用锁定的 `passive 0.2.1`、`std 0.3.0`，绑定 **Yageo RC0603FR-07100RL（100 Ω）**和 **CC0603JRNPO9BN101（100 pF）**。物料来源是仓库现有、已锁定组件包；本轮未重新查询库存或厂家目录。它是独立的现代 0603 RC 连接例子，不是原板通孔器件的等价替换，也没有复现缓冲输出端电容的原拓扑。

```sh
cargo run -- build book/examples/sonde/rc-control --json
python3 book/examples/sonde/run_experiment.py
```

产物在 `book/examples/sonde/rc-control/out/`。INPUT 与 GND 在这个最小例子里是单点被动网络；没有外部连接器、板框、布局布线和功能测量，所以这些产物只证明编译和物料输出流程。

### 故意写错，检查能发现什么

所有修改都在临时测试副本中进行，未改变正式模型或 KiCad 副本。

| 修改 | 实际结果 | 学到什么 |
| --- | --- | --- |
| 将 R2 的 `5.1kohm` 改成 `5.1nF` | E112 | 电阻参数不能混入电容单位 |
| 删除 J1.1 的 NC 声明 | E701 | 必须说明所需 pin 是连接还是明确不用 |
| 将已 NC 的 U2.6 又接入网络 | E702 | “连接”与“明确不连接”矛盾 |
| 把 U1 两个输出并到同一网 | D004 | 当前静态输出角色下会拒绝多驱动 |
| 交换电脑数据/时钟两个端点 | 编译器通过；独立网表对照拒绝 | 类型正确的接线仍可能不符合原设计意图 |
| 合成探针（非器件规格）：写 `supply_min: 4V`，给 VCC 标 `1V` | 仍通过 | 自定义 spec 字段不会自动变成供电下限契约 |
| 合成探针（非器件规格）：写 `voltage_rating: 5V`，给 VCC 标 `6V` | 两个 D001，对应 U1/U2 | 既有额定上限规则确实执行 |
| 把输出角色写成 `tri_state` | E010 | 当前 pin 角色集合没有这个成员 |

两个电压测试中的 **4 V / 5 V / 1 V / 6 V 都是故意设置的合成测试值**，不是 74LS125 的规格或实测值。这里的区别是：`voltage_rating` 已被现有规则识别，随意命名的 `supply_min` 没有这种语义。不能把未触发诊断的 `supply_min` 合成探针描述成“器件工作正常”。

## 当前表达的边界

**三态是明确的抽象边界。** 模型保留输入、输出和供电脚的角色，把 KiCad `tri_state` 输出近似为当前语言的 `output`，并在源码中说明。它能检查某些静态多驱动错误，却不能表达“使能为高时该输出已经释放”，也没有给被动连接器补造外部电脑/FPGA 的行为。

**电压标签不是测量值。** 当前电压 DRC 根据显式 net 电压与器件的 `voltage_rating` 比较上限；它不自动建立供电下限、二极管压降、输入 VIH/VIL 或输出负载条件。原图缺失的额定数据留作缺失，不能通过在注释中写“3.3–5V 可用”来填补。规则实现见 [src/drc.rs](https://github.com/conol-ai/cohdl/blob/9ac0e3c/src/drc.rs)。

**物料缺口和语言缺口分开。** demo 中的 `DB25MALE` 是描述，通孔封装名是几何引用，都不足以确定可采购连接器。现有库中的单门 AHCT 器件也不是原图双颗四门 LS 器件的同一物料。补齐有来源的 part、封装和脚号映射是建库工作；是否新增条件化器件契约才是语言设计问题。

## 把这次证据接到 M1–M4

| 优先级 | 本次观察 / 证据 | 接下来的具体工作 |
| --- | --- | --- |
| M1：关注分离与复用 | 三路 `buffered_path` 展开后仍与原图一致 | 用同类验证检查函数内建器件、跨文件组合、独立实例身份；接口过宽时先收紧 trait |
| M2：编译期编程 | 本次未验证 M2；只确认本板用三次调用即可表达 | 独立做 N 路通道/LED 链例子，验证 N、N−1、越界与稳定展开；不把未来 `for` 写入当前可执行代码 |
| M3：参数化选料 | 阻容值能表达；完整原板缺采购身份 | 先补可追溯元件目录和适用条件，再做参数到候选物料的确定性选择；不能只凭“100 Ω、100 pF”自动宣布电路合适 |
| M4：器件契约 | 三态、外部驱动、供电下限、压降尚需额外事实 | 用这块板提出最小反例，定义条件和 unknown 的语义，再走 RFC；不直接往四条 residual DRC 中加第五条规则 |

研发顺序仍按 M1 → M2 → M3 → M4。学习时发现的电气限制立刻记入器件核对表，不能等语言支持后才处理硬件条件。手表课程会继续沿用这种方法：先描述一个真实电路，再比较连接，再检查具体条件，最后把可重复的问题变成语言验收样例。
