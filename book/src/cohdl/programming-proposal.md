# M2 中文导读：已选 A 的范围与待决问题

> **定位**：参与 CoHDL 语言演进时，理解 M2 要增加什么、哪些取舍尚未决定。前置：[subdesign](subdesign.md)与[十路 RC 实操](../course/03-rc-workflow.md)。本页对应 2026-09-12 修订的[英文工作稿](programming-rfc-en.md)，是导读；[完整中文译文](programming-rfc-zh.md)已同步。用户已选 A，M2 仍为 **Proposed，尚未实现**。

## 先区分已有能力与新增能力

当前 main 的 Accepted RFC-024/032 已支持固定长度的器件数组、subdesign 数组、端口连接、相对布局及内部器件位置覆盖。十路 RC 可以写一个定义，实例化十次，再显式接线和放置；[实操课](../course/03-rc-workflow.md)运行的就是这种写法。

M2 提议加入**带类型、有限、确定的编译期计算与重复**：计算数量、索引和坐标，重复已有的电路操作，同时保留普通器件的类型、引脚与物料义务。循环在编译器里展开；它不描述 MCU 的运行时固件。

## A 已选定，B 延后

| 问题 | A：本轮选定范围 | B：延后比较项 |
| --- | --- | --- |
| 数量、索引、坐标计算 | 共享 Int/Length 计算规则 | 与 A 相同 |
| 重复接线、nc、调用已有 fn；在合法布局体中重复 place | 支持 | 与 A 相同 |
| 数组、fn、subdesign 参数与组合 | 共享同一参数/展开规则 | 与 A 相同 |
| 循环体直接声明 inst 或合法 subdesign 使用点 | 不允许；用循环外具名对象或已有 fn 等组织内容 | 额外允许，每次迭代构造局部对象 |
| 顶层调整第七路电容 | 使用具名 subdesign 数组的内部布局路径 | 同样可用；循环私有局部对象本身没有这个外部访问入口 |

**用户于 2026-09-12 选择先做 A，B 延后。** 已有的具名 subdesign 数组可以支持十路 RC、顶层调整第七路电容和扩到十二路；A 的目标是让其中的数量、接线与放置可计算、可重复。B 若重新提出，需要说明直接循环局部声明解决了哪个具体任务。A 保留现有 fn 创建器件的能力；“fn 退回纯计算”属于另一个需要迁移分析的语言角色提案。见[本次范围决定](../learning/2026-09-12-m2-scope-a.md)。

## `links` 和 placement 各指什么

英文例子里的 `for links: ...` 仍是拟议写法。`links` 给这段重复操作提供诊断来源和生成身份；它不代表 LED 阵列、subdesign 或布局分组。标签是否强制、是否允许省略，仍然待决。

布局沿用所在 design/subdesign 的现有语义：subdesign 内可给默认相对位置，顶层整体放置并覆盖内部器件。A 的循环引用这些已经具名的对象；它不会自动增加坐标系，也不会取消 fn 的布局限制。循环调用 fn 创建的局部器件仍不能通过外部路径单独放置。需要外部调整第七路电容时，应把通道建模成具名 subdesign 数组，使用已有的内部位置覆盖。

A 不允许在循环体内直接写 inst/subdesign 声明，空循环也一样；错误应在声明/上下文检查中发现。把器件声明留在已有 fn 中再调用，仍然属于 A 的范围。这是本轮的明确边界。

循环区间的半开写法与已有含末端的 fan-out 写法需要单独决定，不能从电气用途推出唯一标点选择。

## 与类型系统的关系

```mermaid
flowchart LR
    A[参数种类与声明检查] --> B[具体值计算与边界检查]
    B --> C[有限展开]
    C --> D[最终引脚与端口义务]
    D --> E[已有残余 DRC 与物料检查]
```

Int 数量、Resistance 值和受 trait 约束的器件类型是不同输入，替换时必须保留种类。`n + 1` 即使是 Int，也要对照实际数组长度检查越界；生成十个实例意味着最终检查十套真实引脚。`Pin` 本身不会因此携带已证明的电压或工作电流。

RFC 正文要求一致地检查可静态判定的错误；未知具体值相关的检查等待绑定，最终引脚和端口义务等待电路组装。声明验证器怎样实现、如何衡量旧代码新增报错，放在附录 B 作为后续工作。当前重点是把这些语义要求写清楚。

展开预算的触发检查要沿完整 fn/subdesign 引用图进行，包括深层 helper。纯旧语法设计保持既有计量行为；不能因为新增语法藏在子设计中，就漏掉本应启用的预算。

表达式还需要先有明确的字符解析规则。[09-11 的词法评审](../learning/2026-09-11-m2-minus-lexing.md)发现，当前 lexer 并不支持草案里的 `n-1` 和 `-PITCH`。修订提议让 lexer 单独识别减号，再由 parser 按语法位置区分减法和负号，并保留旧的负数单位字面量。这样，新增计算规则才能与原有数值表示、错误诊断和 fmt 的确定性要求相容；这部分尚未实现。

## 三个场景怎样使用证据

- **LED 级联**：检查相邻连接、边界索引、供电 fan-out 和末端处理。十颗灯的链应有九段相邻连接。
- **多路 RC**：比较定义、十路实例、端口接线、独立布局、单件覆盖和扩到十二路。现有语法基线已经执行；A 的未来循环写法没有执行。
- **嵌套复用**：参数经过 fn/subdesign 多层传递后，类型、端口义务和布局变换仍保持；预算不能漏掉内部工作。

类型正确仍可能接错电路。RC 实操故意合并两路输出后，check 通过但独立通道的拓扑约定失败；这说明需要检查设计意图，并不自动意味着应增加一个新的类型规则。
