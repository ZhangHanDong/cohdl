# 每课记录模板

复制本页的记录块到 `learning/YYYY-MM-DD-topic.md`，加入 `SUMMARY.md`，并从 [进度表](progress.md) 链接到它。空白栏在实操时填写；尚未做的部分明确写“未执行”。

```text
日期与课次：
教材章节链接：
状态：阅读 / 实操进行中 / 完成 / 需要继续验证

练习对象：项目路径、源版本、PCB 文件及版本或 hash
工具：CoHDL、Konnect、KiCad 的实际版本
若有实物：板版本/编号、固件版本、仪器与测试条件

本次问题：
操作前的预测：
实际操作：对象、原值、新值、所用工具/命令
观察结果：原始输出/截图/测量文件的位置
检查：检查对象、规则、错误、警告、未连接项、排除项
修复与重检：

我的复述：用自己的话解释本课概念
仍未验证：缺少哪些条件或证据
应补入 Book 的内容：章节、概念、案例、来源
硬件知识缺口：我还不懂什么，需要资料、计算还是测量
语言表达困难：当前写法、最小困难、预期语义、所属 M1/M2/M3/M4
误解修正：原先的判断 / 新认识 / 支持它的实际观察（未经用户确认不代填）
下一课动作：
```

## 如何写得有用

“移动后 DRC 失败”缺少对象。更有用的记录是“练习副本中的某个 reference 从原坐标移到新坐标；pad 的 net 未变，但新增哪一类未连接项；恢复后该新增项消失”，并链接原始结果。

把观察和解释分开：工具确实返回的坐标是观察；为何某个布局会影响噪声是解释，需要相应电路条件或资料。截图说明可见状态，不能独自证明电流、温升或射频性能。

用户复述由用户提供，AI 可以协助整理并保留疑问；不能替用户编造“已经掌握”。可复用知识进入对应章节，原始实验留在这里。

参考 [课程起点](2026-09-07-start.md)，它只记录目前发生的准备与教材验证，没有虚构 PCB 实操。
