# 2026-09-11：补读最新 RFC 评审，明确减号规则

## 本次实际处理

此前处理的是 08:25 的 Book 评审。用户指出还有更新后，补读到 Claude Code Live **10:59 的 RFC 评审**：M2 草案虽然使用了 `n-1`、`-PITCH`，但没有明确它们与现有负数单位字面量的词法关系。

代理用 main `0e3d770` 的真实 lexer 运行 21 个输入片段。当前 `n-1` 报 E102，`n - 1` 和 `-PITCH` 报 E001；`-1.00mm`、`-40C` 则已经是保留原文本的有效单位 token。这些测量说明当前实现的边界，不是 M2 语法已经可用。

## 如何修订

[英文工作稿](../cohdl/programming-rfc-en.md)和[中文全文](../cohdl/programming-rfc-zh.md)一起补齐 §2 / §10：提议将减号分成独立 token，由 parser 在操作数位置识别负号、在左操作数之后识别减法。旧的紧邻负数单位字面量仍由共享字面量逻辑组装，保留文本和诊断。

评审建议按前一个 token 判断，但 `in` 在 lexer 中也是普通标识符；循环头消费它后，`in -1..N` 中的减号应是前缀。因此角色判断放在知道语法位置的 parser 中，不能仅靠全局 token 回看。

这里也暴露出 fmt 的义务：提议中的 `-1.00mm` 保留原字面量文本，`- 1.00mm` 则是一元算术，结果文本为 `-1mm`。格式化不能把后者悄悄改成前者；否则重编译可能改变下游字节。类型正确之外，还要维护确定性和表示规则。

## 证据与边界

详细评审记录在仓库 `docs/reviews/2026-09-11-m2-minus-lexing.md`，21 个实际探针及可复现源代码在 `docs/reviews/evidence/2026-09-11-m2-lexer-baseline.json`。本页与 RFC 均由 mdBook 构建和链接检查验证；新增的 M2 解析/格式化回归条款尚未执行。
