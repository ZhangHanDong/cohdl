# 第 5 课：手表开发原型

> **定位**：把显示、BLE、运动传感和电源组合成可调试原型。前置：[第一块小板](04-first-board.md)。教材：任务说明；最终 MCU、屏幕、电池和板框尚未选定。

第一版保留可接探针的空间和容易访问的连接器。先在开发板或模块上验证外设与最小固件，再设计自制主板。这样可以分别定位固件、连接和 PCB 问题。

## 从 SF32 样例学什么

仓库的 `examples/sf32-miniboard` 已有 MCU、显示接口、IMU、电平转换、多路电源和调试连接。它是参考起点，目前使用 USB 供电，缺少电池充电；`BRF_ANT` 留空，蓝牙天线未实现；仍需完成放置与布线。

其 60 × 40 mm 板框和 2.16 英寸 AMOLED 不代表最终手表尺寸。显示完整工作电流预算和连接器实物方向也有待确认。先读 [样例 README](https://github.com/conol-ai/cohdl/blob/9ac0e3c/examples/sf32-miniboard/README.md)，再决定复用哪些电路。

## 先做四个独立演示

| 演示 | 需要留下的事实 |
| --- | --- |
| 显示 | 实际模组、板侧连接器、供电与时序；固件能显示测试图案和时间 |
| BLE | 固件版本、连接和校时流程；断开后可重新连接 |
| 运动传感 | 器件、总线、电压域、中断/复位；能重复读出数据 |
| 电源 | 输入来源、系统供电与充电方式；工作条件与测量接入点 |

原型优先评估带既有天线实现的 MCU/BLE 模块。若选择裸芯片，天线、匹配、叠层和射频测试成为单独设计任务。已有参考板上的射频几何依赖其材料与周围环境，不能仅复制图形就宣称可用。

## 再由顶层组合

源文件按 `power`、`controller`、`display`、`sensors`、`ui`、`debug` 组织，顶层显式连接。接口表记录信号、电压域、驱动责任和启动顺序；当前语言表达不了的条件先写入工程说明。

同样的状态灯/按键通道可用于 M2 的后续验证；差异明显的去耦网络先分别表达。详见 [模块与复用](../cohdl/reuse.md)及[语言里程碑](../cohdl/milestones.md)。

## 本课验收

本课验收开发板或模块上的功能演示：显示时间、蓝牙校时、运动数据读取，以及已核对的供电/充电接口与待投板设计。使用现成板的电源也要遵守其资料要求。第 6 课核定自制板的完整电源条件后，才能冻结制造设计；自制板的上电与功能验收在第 7 课收板后执行。

开发板演示、自制 PCB 检查与自制板实测分别记录。计步准确率、完整手表系统和最终续航目标不由这四个演示自动得出。
