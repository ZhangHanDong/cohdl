# 第 2 课：修改、检查与修复

> **定位**：观察逻辑连接保持不变时，物理走线怎样出问题。前置：[第 1 课](01-read-board.md)。教材：教程初版；移动与修复实验未执行。

本课在练习副本中做一次小改动。保留上课记录中的原始网络和 PCB 文件，先知道基线有什么问题，再判断自己新引入了什么。

## 第一步：保存并建立基线

保存当前板，让 Konnect 调用 `run_drc`，记录检查文件、错误、警告和未连接项。当前 wrapper 不保证返回被排除的结果；排除项另外在 KiCad GUI 中核对，尚未核对时写“未检查”。在 GUI 中也找到至少一条对应检查结果；如果没有问题，记录这次检查的范围和规则。

旧 demo 可能包含与本机库或规则有关的告警。先描述它们，不需要为了开始课程把所有告警都改掉。本课关注前后差异；自制板的制造资格则另行验收。

本课程已有一份 [实际基线](../learning/2026-09-07-copper-and-checks.md)：DRC 0 错误、1 警告、0 未连接项；ERC 0 错误、2 警告。DRC 的警告是 J2 嵌入封装与本地库副本不匹配；ERC 的两项是 J1/J2 指向的旧库封装找不到。基线还记录了 4 项忽略测试、空的单项排除列表，以及本次未执行原理图一致性检查。移动实验开始前应再核对文件和规则是否仍与基线一致。

“忽略某类测试”和“排除某条结果”也不同：前者会跳过一整类检查，后者针对具体结果。两者都需要保留在记录中，不能只写最终错误数。

## 第二步：预测 R1 移动后的结果

沿用上一课的 R1。先记录它的位置和两个 pad 的 net，然后回答：“如果只移动封装，原有走线的端点还停在原位置，会发生什么？”

在 KiCad 中亲自使用一次 **Move**；常见默认快捷键为 `M`，以本机设置为准。把器件移到板内可见的空处，避开其他器件。Move 与保持走线跟随的 Drag 是不同操作，本次练习观察普通移动。

也可以让 AI 通过 `move_component` 做同样的移动，但应先读取坐标并说明目标。该调用更新封装位置，不应假定它会自动把所有连接重新布好。

## 第三步：保存、检查、比较

再次读取 R1 的焊盘编号、网络和位置，保存板后运行 DRC。比较：

- reference 和 pad 编号是否仍相同？
- 两个 pad 的 net 是否变化？
- 哪些铜端点没有跟着移动？
- 是否新增未连接、间距或其他问题？

如果这次移动恰好没有产生未连接项，例如焊盘仍接触同网铜区，就记录这个结果，不编造报错。可另选一段已经查询到 UUID 的、连接确实依赖它的走线，在副本删除后检查；先保存恢复点并确认选择对象。

## 第四步：修复

先练习撤销，恢复前一位置并保存，重新运行 DRC，核对是否回到基线。然后如需练习布线，再移动一次，在 GUI 中从目标 pad 开始布线，按规则完成连接；铜区存在时重新填充，再保存并检查。

本课没有“所有板都适用”的线宽和移动距离。使用练习板的规则，具体值要能在项目设置里查到。

KiCad 官方入门也采用“故意造成问题 → 运行 DRC → 修复”的练习方式。[KiCad 10：Design rule checking](https://docs.kicad.org/10.0/en/getting_started_in_kicad/getting_started_in_kicad.html#design_rule_checking)。

## 这件事如何对应 CoHDL

源代码里的连接没有变时，`cohdl check` 可以继续通过；移动 PCB 器件造成的断线需要检查实际板。两者检查不同对象。详见 [从 check 到实际 PCB](../cohdl/pipeline.md)。

## 本课完成条件

保存一次实际的“预测、改动、观察、修复、重检”，并能解释新增问题为何出现。没有观察到预期问题也可以作为实验结果，但必须查明原因；本课至少完成一次可复现的问题与修复闭环后再标为完成。
