## 哪些意见成立，哪些需要限定

| 评审观点 | 核对结论 |
| --- | --- |
| 给 RFC 的 tscircuit 引用补上具体机制 | 采纳：固定提交中的未命名计数器、选择器递归、重名错误处理可以直接支撑比较 |
| tscircuit 是 B 的反证 | 不采纳这个强结论。map 例子使用现成字符串名称列表，并没有字符串插值；它不能直接替 B 的私有局部对象提供外部地址，但局部构造在自身作用域内仍可能有价值 |
| 编辑一处会让身份全部漂移 | 证据不足。计数器证明未命名元件的顺序依赖；显式名称和 Circuit JSON 内部 ID 是不同层次，不能从序号形式推导全部编辑行为 |
| 选择器能进入子电路，因此边界有漏洞 | 前半句有源码支持；后半句不成立为缺陷判断。tscircuit 支持层级选择器，CoHDL 要求电气端口边界，二者契约不同 |
| tscircuit 内层放置覆盖外层，方向相反 | 所读具体冲突成立：元件有 pcbX/pcbY 且存在 manualEdits 时，前者胜出并记录 warning。这不能概括所有嵌套布局优先级 |
| 错误即数据无法满足同源同字节 | 不成立。确定性与成功判定独立；错误模型也可能确定。应要求失败状态明确、成功构建不得悄悄丢元件 |
| 渲染会携带错误一直跑完 | 过于绝对。重名路径记录错误并标记移除，但 Renderable.renderError 直接抛出异常；不能假定所有错误都会继续 |
| group 端口都由连接派生，因此没有声明式接口 | 源码只证明 showAsSchematicBox 与 connections 同时存在时的一条补端口路径，不能外推整个端口模型 |

同样，未在有限搜索中找到构造预算，并不是审计了所有宿主求值/沙箱/工具层。可以说所读实现没有建立与 M2 相同的语言级计量契约，不能声称整套工具在任何阶段都无资源限制。单位写法的测试文本可供研究，但不将文本计数记为本轮执行结果。

## RFC 的三处补充

英文为准，中文同步：

1. 非目标之后增加固定提交证据，将未命名计数器与层级选择器和 CoHDL 的位号/端口契约作有限比较。
2. Alternatives 第 4 项明确 map 同时使用构造与外部命名；该例不能单独证明 B 对后续外部放置任务的必要性，也不是对 B 全部局部构造能力的反证。
3. Failure modes 明确带错误的编辑器模型不等于成功构建，同时避免将错误记录与非确定性混为一谈。

没有改变 A/B、类型系统、词法规则、预算或诊断契约。M2 仍为 Proposed；候选、标签及区间范围未决，`lib/` 新旧验证器审计未执行。
