## main 基线与必须完成的组合修订

当前 [RFC-032](https://github.com/conol-ai/cohdl/blob/0e3d7705ab393a5c64c20836540ad1bc2e49898e/docs/design/rfc-032-subdesign.md)、[note 10](https://github.com/conol-ai/cohdl/blob/0e3d7705ab393a5c64c20836540ad1bc2e49898e/docs/design/10-language-specification.md) 和[实现偏离记录](https://github.com/conol-ai/cohdl/blob/0e3d7705ab393a5c64c20836540ad1bc2e49898e/docs/compliance-report.md)确立以下基线。恢复此依赖，并不自动解决每个 M2 候选构造与它的组合方式。

| 构造 | 既有职责 / 提议边界 |
| --- | --- |
| `module` | 通过 RFC-016 管理名称、导入与可见性 |
| `subdesign` | 已接受的带类型逻辑组合：显式 Pin 端口、具名层级、泛型替换、数组、嵌套组合、默认相对布局、整体放置与显式内部放置覆盖 |
| `fn` | 既有的内联电路展开，可产生电路并绑定 Pin/Instance 实参；没有供外部放置局部实例的接口。RFC-032 保留这一职责 |
| `for` / 标签 | 提议的有限重复与迭代身份；`links` 这样的标签目前命名生成位置，不是 subdesign、布局组或可公开寻址的数组 |
| 纯表达式 | 提议的、经过检查且不产生电路效果的 Int/Length 值计算；把 fn 改成返回值的纯函数，需要另作明确的兼容性决定 |

subdesign 的电气引用仍经过端口；放置可以访问其真实内部实例。subdesign 容器不是物理 Instance，没有 BOM 行或位号，不能仅因有名字就替代 Instance 类型的 fn 实参。端口连接必须保留自己的 required 端口检查，以及物理引脚的最终义务。实现拒绝对端口使用 `nc`，也拒绝在 fn 体内实例化 subdesign；这些是应纳入考虑的既有边界，M2 不能悄悄赋予它们新含义。

**本提案须解决以下设计问题，才具备接受条件。** 下文针对 fn/物理数组的详细候选方案仍是评审材料，并非完整的 subdesign 可编程规范。其中仅限 fn 的数量参数、design/fn 体白名单、物理数组 `.len`、仅限 design 的循环放置、只遍历 fn 的预算规则，都必须在实施前与 RFC-032 明确协调。既有 subdesign 行为持续有效；“M2 不新增”绝不表示“CoHDL 没有”。

1. 通过共享泛型/数组机制规定 subdesign 的 Int 参数、表达式数量/选择器与常量，或逐项论证分阶段限制。不得引入独立的参数或索引系统。
2. 规定 subdesign 内部重复及重复实例化 subdesign 的行为，包括端口类型、包含环、所属关系、布局坐标系，以及逻辑节点和端口操作的资源计量。只遍历 fn 引用无法约束会展开 subdesign 的设计。
3. 比较既有“产生电路的 fn + subdesign”与另行提议的纯 fn 模型。迁移分析须覆盖现有 Instance 类型 helper 和物理属性目标。专家的问题促成这一比较，不等于已经接受破坏性变更。
4. 完成一个贯穿评审场景：定义 RC 通道 → 实例化十路 → 通过端口接线 → 在独立 layout 块放置 → 覆盖第七路电容 → 扩展到十二路 → 比较既有物理路径、位号、连接与位置。保留局部 inst 例子作为作用域/类型探针，但不能仅凭它证明可复用通道的完整流程可用。另行决定：对已有具名数组只做接线的循环，是否仍须强制标签。

**规范与实现的已知差异继续明示。** RFC-032/note 10 把 fn 描述为同包复用，但 RFC-016 的名称解析和现有 `pub fn` 实现支持跨包调用。应以保留的接口与放置访问解释区别，并通过既有治理流程协调包能力的矛盾表述。RFC-032 还要求已检查 IR 保留层级；当前 `src/ir.rs` 公开的是平铺物理设计，具名 subdesign 结构保存在展开过程中，并反映于子实例路径。不能据此推断完整的公共层级模型或 Explorer 支持已完成。这些观察限定实现声明，不撤销已接受的 RFC-032。

## 问题

CoHDL 已能描述器件、物理实例、连接、可复用 fn 及已接受的 subdesign 组合。RFC-024 增加字面量数量和索引的 `[Device; N]`，但明确将数量相关的接线与放置留给手写。一个电路板系列还需要重复整个通道：创建其中的电阻、电容，连接它们，再把通道组合进另一份可复用定义。

仅增加 `for` 的 RFC 没有回答核心问题：程序能计算什么、构造什么，值与物理对象有什么区别，以及生成过程保留哪些检查？用户需要修改通道数量或复用电路，同时保持单位安全、引脚义务、稳定的物理身份和编译器解释失败的能力。

使用者是生成/修复 `.cohdl` 的 AI、审查设计的人，以及组合参数化电路的库作者。下述三个验收场景是语言契约测试，不声称 LED 链或 RC 网络已经是经过验证的硬件产品。

## 目标

1. 独立于具体循环拼写定义 CoHDL 可编程能力，明确输入、值域、构造效果和检查阶段。
2. 通过共同机制表达级联、多元件重复通道和嵌套参数化 fn 组合。
3. 保留构造前的单位/trait/参数种类检查，以及组装后每个真实实例的连接义务。
4. 确定性地拒绝具体值错误与过量展开，保留源表达式和可区分的调用/迭代上下文。
5. 保留既有数组身份和旧输出，规定新生成对象在编辑后的身份稳定边界。
6. 为 check/build、fmt、LSP、文档与 Explorer 交付同一语义；cohdl.ai 使用它而不重新实现它。

这些目标服务于宪章第 1–5 优先级：正确性/机器可检验性、AI 可生成性、人的可审查性、可组合性和忠实输出。减少书写是收益，不构成正确性证据。

## 能力模型：CoHDL 应该能编程什么

**CoHDL 的可编程能力，是根据显式参数和经过检查的编译期计算，构造有限的电气设计，并使其中的实例、连接和已声明约束继续接受普通编译器契约的检查。** 这是设计时计算；循环和变量不会变成制造后在板上运行的固件。

完整能力模型与本次 M2 的提议范围明确区分：

| 能力 | 对 CoHDL 的含义 | 本次 M2 提案 / 剩余工作 |
| --- | --- | --- |
| 参数与值计算 | 从显式输入推导设计数据 | 增加 Int/Length 表达式、局部常量和 fn 数量参数；保留其他已有单位字面量/参数转发。一般量纲公式及返回值函数需要后续契约 |
| 电路构造 | 根据数据创建真实实例和显式连接 | 在有限的电路体循环中允许标量/数组 inst、net、nc 和既有 fn 调用；不生成源码字符串 |
| 重复与组合 | 构造 N 路通道，再在另一份定义中复用 | 扩展物理数组选择器，让具名 for 与既有 fn、泛型绑定嵌套；fn 仍是产生电路的片段，不是可作为值返回的电路对象 |
| 配置选择 | 从已声明的备选中选择电路形式或固定器件 | 保留既有类型实参与 RFC-008 结构变体；零次或多次构造已经由数量控制；通用 Bool/if、分支选择和分支专属检查暂缓 |
| 领域配方 | 根据电压/电流要求推导元件参数并选择合适物料 | M3 必须规定量纲公式、适用器件事实、选型策略和固定结果；M2 提供组合/数量机制，不提供这个求解器 |
| 可检查的电气契约 | 声明并验证所选/所生成设计的义务 | 保留现有单位/trait/引脚检查与恰好四条残余 DRC；M4 必须分类新增契约、依据和缺失数据行为，不承诺任意运行时 assert |

普通参数化 fn 已能转发显式的电阻/电容值。暂缓一般电气公式，不等于暂缓这些已有带类型值。同样，显式传入固定 part 不等于自动选型。MVP 可以实现这一模型中有边界的一部分，无需把这部分称为通用编程语言。

### 值、引用与构造效果

三类事物必须保持区别：

- **值：** Int 数量/索引及物理量。求值只产生一个值，不修改电路、不执行 I/O、查询 registry 或分配物理元件。M2 只扩展 Int 和 Length 的算术。
- **引用：** 既有 Instance/Pin 绑定及物理数组的索引引用。它们标识真实对象；裸数组不是 Instance 或 Pin。引用不能相加、序列化成生成的标识符，或用于检查未声明的电气事实。
- **构造效果：** inst 贡献物理实例；net 贡献连接；nc 贡献显式不连接决定；fn 贡献展开的电路片段；layout 贡献既有放置/约束事实。for 重复其中允许的构造效果；const 不产生这些效果。

标量 inst 声明在每个实际进入的帧中创建一个真实实例；数组 inst 声明在每个进入的帧中创建其求得正长度个真实元素。引用同一实例两次，不会构造两个元件。调用产生电路的 fn 两次，会创建两份局部元件，不能像纯表达式那样通过记忆化消除。M2 没有对象返回/集合 API、可变电路图 API 或隐藏的自动接线。数组声明提供可从外部逐项引用的实例族；迭代局部声明提供重复的私有实现细节。

### 检查契约属于能力本身

输入有类型，并不足以证明展开会产生合法电路。本 RFC 要求分阶段契约：

| 阶段 | 已有信息 | 必须履行的义务 |
| --- | --- | --- |
| 定义/类型验证 | 声明的类型、名称、trait 和具体子表达式 | 解析符号与引脚成员；检查参数种类、单位兼容性和新增构造，覆盖未使用/空体，但遵守设计第 8 节的兼容边界 |
| 绑定与有限展开 | 实际泛型值、数组长度及每次进入的循环值 | 检查整数值域、边界、精度、操作上下文和预算；创建隔离名称且带来源信息的对象 |
| 最终 design 组装 | 全部生成实例、net 和 nc 决定 | fn/循环展开后应用 RFC-002 引脚穷尽性及普通网络合并/冲突检查；不提前逐 helper 检查穷尽性 |
| 残余 DRC | 组装后的图与明确建模的电气事实 | 原样运行已有四条规则；结构性的索引/类型错误不成为第五条规则 |
| 构建与投影 | 已检查设计、物料、锁和引用资源 | 对每个真实实例执行已有 part/封装/分配/输出契约；循环不产生虚假 BOM 行，也不允许部分构建成功 |

这是**类型系统优先，而非只靠类型系统**。Int 仍可能越界，类型正确的连接仍可能接到错误的预期通道，通过已有 DRC 也不证明模拟电路响应。它们分别需要具体值检查、独立拓扑对照或领域/物理证据。Pin 参数并未变成新增的以电压为索引的依赖类型。这里不证明所有可能的 const 泛型实例化都合法：每次实际调用接受检查，信息充分时更早拒绝与未知值无关的错误。

## 与 CoHDL 类型系统的关系

### 扩展带类型的构造，保留既有电气模型

M2 扩展语言的编译期值与构造机制，不替换 Device、Part、Trait、Pin 或其已有契约。这个区别很关键：让数量可以计算，不会新增一种电气单位；重复声明，也不会削弱所声明器件的类型。

| 既有机制 | 与 M2 的关系 | 具体验收义务 |
| --- | --- | --- |
| RFC-001 物理单位类型 | 保留全部已有单位身份与零隐式转换；增加规定的精确 Length 算术，Int 是独立的结构值域 | `100nF` 不能绑定 R: Resistance；`10mm + 2` 失败，`10mm + 2 * 1mm` 的类型是 Length |
| RFC-003 trait 满足关系 | 每个具体器件替换仍需满足 impl 及 trait 引脚/spec 映射 | 即使经过重复 helper，传入缺少所需 Capacitor impl 的器件仍然失败，不能因器件本身合法就放行 |
| RFC-007 泛型参数 | 经同一绑定/替换机制为 fn 增加结构参数 `const N: Int`；保留单位值和 trait 约束类型参数 | 嵌套调用转发 N、R、C 时保留各自种类；默认值不能抹掉预期种类 |
| RFC-024 物理实例数组 | 扩展数量/索引的表达式位置，保留物理元素类型与真实身份 | `[D; N]` 的 N 必须求得正 Int；每个被选择元素都有 D 的同样已解析 spec 与引脚义务 |
| RFC-006 fn 与引用绑定 | 复用 Pin/Instance 绑定及产生电路片段的展开 | Pin 实参引用已有物理引脚或允许使用的 subdesign 端口；helper 调用两次产生两套局部元件，不是复制传入对象两次 |
| RFC-002 引脚义务 | 保留最终组装时的穷尽性 | 循环或嵌套 fn 创建的每个实际实例都参与，包括调用者接线完成后才暴露漏接的情况 |
| RFC-004 残余 DRC | 保留现有四条整体图规则 | 类型不匹配和具体索引错误都不转移到新增 DRC 规则 |

### 三种泛型输入，共享一套替换规则

例如声明 `fn bank<const N: Int, R: Resistance, D: Capacitor>(target: D, pin: Pin)`，N 是结构整数值，R 是 Resistance 值，D 是受 trait 约束的器件类型。它们不是无类型参数的三种不同拼写。`target` 是按照 D 检查的实例引用，`pin` 是引脚引用，都不是可计算标量。

当前实现通过 `GenericBound::Unit`/`Traits` 与 `GenericValue::Unit`/`Device` 表达已有区分（`src/ast.rs`、`src/check/generics.rs`）。M2 需要独立 Int 分支，以及能保留类型与 span 的默认值/实参表示。不能把 N 塞进伪造的 UnitValue、从字符串猜种类，或只为循环增加另一套泛型实参解析与绑定机制。这些实现位置解释了二者关系，具体 Rust 变体名不是公开语言语法。

同样，已有 trait 约束描述器件的义务，不是数量值上的任意谓词。N > 0 在数组长度的使用处检查，不会悄悄变成一种新 trait。通用 where 子句、精化类型和任意整数定理证明器均不在 M2 范围内。

### 类型已知，不等于数值已知

绑定泛型 N 之前，编译器可以知道 N 是 Int，但不知道它是 3、0 还是负数。因此它可以在类型验证时拒绝 `N + 1mm`；而 `[D; N]` 是否具有合法正长度，要等 N 具体化后检查。同样，`leds[n + 1]` 的索引类型可能正确，却在最后一次迭代违反具体边界。

数组形状在这个有限意义上依赖数值；M2 不引入通用依赖类型系统、不对所有可能索引进行编译期证明，也不在实体电路板上做运行时越界检查。它检查每次实际实例化/迭代，并在接受设计前拒绝非法构造。设计第 8 节的空循环规则仍要拒绝无需绑定未知值即可确定的错误，不为未绑定循环变量编造值。

```cohdl
// Proposed negative example: no concrete value for C is needed to find the unit error.
fn wrong_channel<C: Capacitance>() {
    for empty: i in 0..0 {
        inst r: SeriesR<C>
    }
}
```

新循环体必须失败，因为 SeriesR 要求 Resistance，而 C 的类型是 Capacitance，即使它不创建任何 r。相对地，依赖未绑定迭代值的除法遵守设计第 8 节精确定义的延后检查边界。这是类型信息与值信息的区别，不是跳过未使用体检查的许可。

### 连接义务在构造后组合

普通 `Pin` 类型确定引用种类，不声明引脚具有某个运行时电压或最大安全电流。这些事实必须来自已建模 spec/注解与适用检查，或未来电气契约提案。因此，电阻参数的类型不能证明整个 RC 网络具有预期传递函数。

helper 可以只连接调用者拥有器件的一部分引脚。其未解决 required pin 继续是最终 design 的义务，不能提前拒绝，也不能在 helper 返回后被丢弃。for 重复同样的片段行为。全部真实实例和连接确定后，既有最终组装检查每个义务，保留未提及 required pin、显式 nc 和已连接引脚之间的区别。

构造保持保证的要求是：在声明的源码对应关系下，每个生成实例与显式对应实例具有相同的已解析 device/spec、trait 角色映射及引脚义务；生成图接受相同的普通检查。这是用成功与失败样例验证的实现验收性质，不声称本 RFC 包含形式化健全性证明。连接仍可能不符合用户意图却通过这些检查，因此独立拓扑对照仍然必要。

### 类型边界决定实现顺序

先实现带类型表达式和共享泛型替换，再允许循环生成对象；随后补齐新帧的声明验证、具体求值/展开，以及最终图/来源信息集成。仅在 parser 接受 for、为循环做专属字符串替换，或由编辑器独立展开数组，都不能满足契约。工具必须报告与编译器一致的区分：符号的类型、已绑定的值，以及组装后的电路。

## 定义成功的三个场景

这里所有片段都使用提议语法和人工定义的器件接口。完整的当前语法对照与未来 `.cohdl.txt` 文件位于 `docs/proposals/fixtures/m2-programmability/`。它们仅用于 check；有真实物料绑定的 build 用例仍是单独的实现验收门槛。

### A. LED 级联：计算引用后仍保留引脚义务

```cohdl
// Fragment of the complete LedChain fixture; host and LED interfaces are defined there.
const N: Int = 10
inst leds: [AddressableLED; N]
net VCC [5V]: host.V5, leds[0..=(leds.len - 1)].VDD
net GND [gnd]: host.GND, leds[0..=(leds.len - 1)].GND
net DATA: host.DATA, leds[0].DIN
for links: n in 0..(leds.len - 1) {
    net _: leds[n].DOUT, leds[n + 1].DIN
}
nc: leds[leds.len - 1].DOUT
```

N = 1/2/10 时，分别贡献 0/1/9 条相邻连接。电源 fan-out 贡献一条共享网，不是 N 条独立连接。N 和每个索引必须是 Int，`n + 1` 根据实际数组长度检查。删掉生成的电源连接后，最终组装仍必须发现未解决的 required pin。显式将电源引脚标记为 nc 满足既有结构决定规则，但不证明适合上电工作。

### B. RC 通道：同时构造器件和连接

```cohdl
// Fragment of FilterBank. SeriesR/ShuntC have typed resistance/capacitance parameters.
// inputs and outputs are N-element arrays; ground is a real reference instance.
for channels: i in 0..N {
    inst r: SeriesR<1kohm>
    inst c: ShuntC<100nF>
    net IN: inputs[i].OUT, r.A
    net FILTERED: r.B, c.A, outputs[i].IN
    net GND [gnd]: ground.GND, c.B
}
```

每次迭代创建各自的 r、c 和局部 IN/FILTERED 网络。不同迭代的 GND 合并，是因为每次显式包含同一个 ground.GND 引脚，不是因为打印出的名称相同。十路通道在接口实例之外，还需要十颗电阻和十颗电容。

`SeriesR<100nF>` 必须在单位替换时失败；删掉 c.B 的网必须导致引脚义务失败；意外通过同一引脚把所有 FILTERED 短接，可能仍类型正确，因此需要参考拓扑对照。所选数值不证明截止频率、容差预算或源/负载适用性。本场景说明循环内直接 inst 的必要性：提取 helper 是作者的选择，不是生成局部物理对象的前提。

### C. 嵌套复用：替换与义务可组合

```cohdl
fn rc_channel<R: Resistance, C: Capacitance>(src: Pin, dst: Pin, gnd: Pin) {
    inst r: SeriesR<R>
    inst c: ShuntC<C>
    net IN: src, r.A
    net OUT: r.B, c.A, dst
    net GND [gnd]: gnd, c.B
}

fn filter_bank<const N: Int, R: Resistance, C: Capacitance>(src: Pin, gnd: Pin) {
    inst receivers: [SignalSink; N]
    for channels: i in 0..N {
        rc_channel::<R, C>(src, receivers[i].IN, gnd)
    }
}

// Call fragment in a design with real source and ground interface instances:
filter_bank::<3, 1kohm, 100nF>(source.OUT, ground.GND)
```

外层绑定提供 N、R、C；每次内层调用转发同样的带类型物理量及不同的接收引脚。即使经过两层 fn，将 R 替换为 Capacitance 仍然失败。需要 Pin 的位置传入实例，由已有种类检查拒绝；既有 trait 约束实参仍必须有满足要求的 impl。helper 可以把调用者拥有的引脚留给调用者连接，只有最终组装决定穷尽性。不需要新的 fn 返回类型、虚拟接口对象或跨边界访问语法。

完整三通道对照的结果必须是三颗接收器、三颗电阻、三颗电容，再加源与地接口。共享输入及三条独立滤波输出必须与显式对照一致。针对组合本身，按物理图比较直接构造、每通道一个 helper，以及 helper 调用参数化 bank 的形式，不比较生成路径的拼写。三种写法都使用场景 C 相同的共享输入接口/拓扑；场景 B 有独立输入，与自己的对照比较，不声明它与 C 等价。

## 非目标与明确的范围选择

- 运行时执行/固件、while、递归、可变状态、break/continue、任意迭代器、I/O 或依赖环境的求值。
- 通用 Bool/if、分支选择语义、返回值 const fn、一般量纲代数及自动选型。包括由数量控制的拓扑：循环上界为 0 或 1 可以省略或加入局部支路。这不引入短路式分支检查、零长度物理数组或选型策略。一般配置仍需明确的分支检查/身份及器件事实契约。
- 新电气断言、推断引脚电压/电流、通用约束求解器、仿真或新残余 DRC 规则。
- 多维数组、数组值 fn 参数、逃逸的迭代局部引用、返回电路集合、字符串插值或生成源码标识符。

## 设计

### 1. 含义：有限构造，然后执行既有检查

三个场景定义了电路构造效果。for 对静态有限范围中的每个整数展开其允许的体；局部 inst 贡献真实元件，net 贡献与普通语句相同的连接关系。制造 IR 中没有循环指令或虚假容器元件。下述规则为这些场景及其组合定义一套求值与展开机制。

### 2. 一个表达式模型，两个值域

新求值器处理 **Int**——用于结构的有符号精确 64 位整数——以及现有 **Length** 类型。Int 不是第十二种电气单位，也不是省略后缀的隐式物理量。其可表示范围为 −2^63…2^63−1；字面量和每个中间值都要检查。零和负的中间整数是合法值；每个使用该值的操作再施加自己的值域限制。

| 运算 | 结果与规则 |
| --- | --- |
| Int `+ - *` Int；一元 `+ -` Int | Int，检查溢出；不回绕，不饱和截断 |
| Int `/` Int | Int，商向零截断；除数为零及 MIN/−1 都是错误 |
| Int `%` Int | Int，余数满足 a = (a / b) * b + r；除数为零及 MIN/−1 都是错误 |
| Length `+ -` Length；一元 `+ -` Length | Length，沿用既有精确定点表示 |
| Int `*` Length 或 Length `*` Int | Length，检查精确缩放；Int 不会被转换成 Length |
| Length `/` Int | 仅当结果可以精确表示时得到 Length；除数为零、溢出或精度损失均为错误 |
| Int `+` Length、Length `/` Length、Length `*` Length、其他单位算术 | 本 RFC 中拒绝 |

因此，`10mm + n * 4mm` 合法；`10mm + n`、`3.3V + 1V` 和 `1mm / 0` 不合法。若 `1mm / 3` 无法精确表示，则拒绝而不舍入。求值后仍执行现有物理坐标范围检查，不依赖平台 libm。

Length 沿用现有的 **以 10^-15 mm 为单位计数的有符号 i128**（`UnitValue.femto`）；表达式中间值按此表示检查。几何使用方更窄的范围限制在既有使用阶段施加，不施加于所有常量或泛型值。算术派生的 Length 值按既有 `geom::mm_femto` 约定生成规范文本：最短十进制后接 `mm`，无多余尾零、无负零。因此 `1.00mm + 0mm` 产生值文本 `1mm`。字面量、字面量外的括号，以及纯参数/常量转发保留原值文本；算术运算——包括 `-PITCH` 这样作用于值的一元运算——生成规范结果文本。属于既有带符号单位字面量的符号仍是字面量的一部分：`-1.00mm` 保留原拼写。源码格式化另行保留表达式 AST。任何输出器都不得自行发明拼写，也不得将未求值的表达式放进 `UnitValue.text`。

整数字面量采用十进制整数；不引入新进制或小数拼写。直接作用于十进制字面量的前缀符号，在 Int 范围检查前与其绝对值合成，因此 `-9223372036854775808` 是合法字面量/默认值，而 `9223372036854775808` 不是。其他一元运算按通常方式检查溢出：若 MIN 已是一个 Int 值，`-MIN` 会失败。给带符号字面量加括号会保留它；给超范围的正绝对值加括号，并不会使该绝对值合法。必须明确测试 MIN、MAX、两侧相邻的越界值、对 MIN 取负、MIN/−1，以及负默认值。

运算符优先级从高到低为：基本表达式/括号 → 一元运算 → `* / %` → `+ -` → 区间分隔符。二元算术左结合。比较、布尔值、类型转换和幂运算不在语法范围内。按源码表达式树的顺序求值；重新结合运算不得隐藏溢出。

### 3. 局部常量与整数泛型参数

```cohdl
design Board {
    const COUNT: Int = 10
    const COLUMNS: Int = 5
    const PITCH: Length = 4mm
    inst leds: [AddressableLED; COUNT]
    // Explicit wiring follows.
}

// Declaration fragment, proposed syntax:
pub fn led_chain<const N: Int>() {
    // Instantiates and wires N LEDs using the existing fn model.
}
```

局部 `const NAME: Int|Length = EXPR` 可用于 design、fn、循环和 layout 体。它不可变，没有运行时或 IR 身份，也不是顶层包声明。其表达式可以使用可见常量、相关的现有 Length 参数、整数泛型参数、外层循环变量，以及下文定义的 `.len`。它不能读取引脚电压、实例 spec、registry、文件或已经生成的布局位置。

**`const N: Int` 扩展现有泛型参数列表**，最初只用于 fn 声明。使用处沿用既有调用形式：`helper::<10>(...)`。Int 默认值必须显式写成整数字面量，例如 `const N: Int = 10`；现有单位默认值规则不变。Int 实参可以是整数表达式。Length 实参可以使用这套求值器；其他物理单位类型的实参仍沿用既有字面量/参数规则。缺少实参及现有 trait 约束检查保留既有机制和错误码。

`const` 标记将这种新的结构参数与名为 `Int` 的 trait 约束区分开来：如果该 trait 存在，既有 `N: Int` 仍表示 trait 引用。这也避免将既有 device 的泛型声明静默重新解释为数量。`const` 形式中的上下文 Int 注记不将该名称变成全局保留的声明名。不建立第二套实参绑定算法：在共享的 RFC-007 替换/检查机制中增加整数值分支，包括未使用定义的验证。

本提案不允许 device 声明上的整数泛型：改变器件的物理引脚接口是另一问题，已由结构变体管理。Int 不能用作 device 的电气 `spec` 值。这项限制必须给出有针对性的声明错误，不能只是解析器没有覆盖，也不能把参数静默当作未使用。device 的单位类型泛型和 trait 约束泛型保持不变。

同一词法体中的常量和数组长度形成无环依赖图；允许在该体内前向引用。按确定性的依赖顺序求值，并对 `const N: Int = leds.len` 加上 `inst leds: [T; N]`，或相互依赖的常量报告完整环路。子作用域的常量不会对父作用域或兄弟作用域可见。layout 体内的常量只在该 layout 及其后代作用域可见。

新增常量、循环标签和绑定变量不得与可见的局部实例/数组、网络、fn 参数、泛型参数、常量或外层循环标签/绑定变量重名，也不得遮蔽它们。循环标签属于包含它的体，检查标签唯一性时 layout 块不形成额外边界；绑定变量仅属于该循环体。重复的 const/instance/array/loop-label 声明是错误；重复声明同一具名网络则保留现有的网络续接语义。互不重叠的兄弟循环可以都绑定 `n`，因为绑定变量分别属于不同的局部体。

### 4. 扩展现有数组选择器，不另造一种数组

数组长度接受 Int 表达式，并保持**严格为正**。`[T; 0]` 仍是 E211；本 RFC 不引入零长度物理实例数组。常量泛型 N 必须在每个实际使用处满足此规则。

`ARRAY.len` 以 Int 返回物理实例数组声明的长度。这是唯一新增的数组查询，不是方法或通用字段访问机制。它仅允许在表达式上下文中作用于可见数组名，不产生元件。`inst x: T` 没有 `.len`；未加索引的数组仍不是 Instance 或 Pin。它不增加跨越组合边界的点号访问。

所有既有单索引位置都获得相同的 Int 表达式支持：

- net 或 nc 成员中的 `leds[n + 1].DIN`；
- 指定一个元素或其引脚的 fn 实参；
- design 自身布局中的 `place leds[n] ...`，不增加新的内部对象访问路径。

区间/列表 fan-out 仍然**仅允许作为 net 成员**，保留既有的含上界 `..=` 和可选 `step` 写法。其边界、列表项和步长现在可以是 Int 表达式；步长必须为正，且起点 ≤ 终点。检查每一个具体选中索引，绝不裁剪区间。`leds[0..=(leds.len - 1)].VDD` 将这些引脚接到**同一条**网络；它不生成数据级联链。

### 5. 有限 `for` 与允许的循环体

```text
for_stmt       := 'for' LABEL ':' IDENT 'in' expr '..' expr '{' loop_stmt* '}'
const_stmt     := 'const' IDENT ':' ('Int' | 'Length') '=' expr
int_parameter  := 'const' IDENT ':' 'Int' ('=' integer_literal)?
primary        := literal | IDENT | IDENT '.' 'len' | '(' expr ')'
```

循环展开前，其边界必须求得 Int。`a..b` 按升序迭代 a、a+1、…、b−1。**a = b 为空；a > b 为错误**，并提供修正区间的提示。允许带符号边界；负值一旦用作数组索引仍会失败。本提案不引入含上界的 `for a..=b`，也不引入 for 步长子句。允许嵌套循环，且可依赖外层绑定变量。绑定变量只读。必需的标签是该循环站点稳定的词法身份（第 7 节），不是 Instance、Pin 或值。在本提案中，匿名 `for n in ...` 不是另一种可接受拼写。

在 design/fn 体内，循环体允许局部 const、**标量和数组 inst**、net、nc、既有 fn 调用、嵌套 for，以及包含下述放置子集的 layout 块。inst 复用普通的 device/part/泛型检查与属性，不是另一种生成器件声明。先收集迭代帧的声明，再处理其操作，保留已有声明与使用的顺序灵活性。循环内外数组使用相同的正长度及元素规则。循环局部数组仍是一维；嵌套循环不引入 `a[i][j]`。

循环局部实例/数组在该次迭代及其词法后代中可见，包括嵌套循环或合法 layout 块。其引用可以传给既有 fn 调用，但不能被兄弟迭代、包含循环的体，或 `channels[2].r` 这样的外部路径表达式访问。后续操作需要引用全体元素时，在包含循环的体内声明数组。迭代局部实例/数组名不得遮蔽可见实例/数组名、Pin/Instance 参数、泛型参数、常量或绑定变量；帧内重复声明为 E201。局部网络名遵循第 7 节明确的名称隔离规则。

不允许顶层定义、导入、新物理形状或逃逸引用。在 layout 块内，for 只允许 const、place 和嵌套 for，不允许 inst 或电气连接语句。电路体循环内的 layout 块也只有这个放置子集。循环外普通 layout 块保留既有约束。被调用 fn 保留普通合法体，包括 inst 和既有布局约束。词法白名单不禁用这些已有 helper 操作，产生的全部工作仍计入预算。

**对象所属的 design 或 fn 从包含它的体继承，不从生成路径字符串推断。** 直接位于 design 的循环可以创建 design 所属局部实例，其 layout 可以放置词法可见且属于 design 的任何实例，包括自己的 r 或 c。这显式将 RFC-020 仅顶层放置目标的限制扩展到 design 所属循环局部实例，不允许进入 fn 内部。fn→for→layout→place 仍为 E1007，被调用 fn 中的板框仍为 E1006。循环不会创建新电气接口、坐标系或覆盖层。已有 RFC-006 环路检查在实际到达活跃递归调用时拒绝它，即使被调用方中的循环随后为空；它不要求证明所有假想参数下的普遍终止性。

### 6. 通过公式计算放置

```cohdl
layout {
    for grid: n in 0..leds.len {
        place leds[n] at (10mm + (n % 5) * 4mm,
                         10mm + (n / 5) * 4mm)
    }
}
```

这段代码描述所声明元件原点的五列网格。它不进行碰撞、间距、热或布线优化。`at` 接受 Length 表达式；`rotate` 接受 Int 表达式，但仍按当前 0…359 规则检查，不将 360 回绕为 0；`side` 保留现有的 top/bottom 字面选择。焊盘/封装几何表达式及新角度类型不在范围内。

**循环的词法帧不创建坐标系或放置覆盖层。** 在 design 自身布局中，计算位置使用既有板坐标系；rotate/side 作用于单个物理实例。循环内放置与相同的显式放置遵守同一重复放置规则（E1007）。迭代顺序绝不引入“最后写入者获胜”的放置语义。既有整组变换、默认相对布局及从外部覆盖内部实例位置的行为仍由 RFC-032 规定。它们与 M2 循环的组合须在前述组合修订中明确。

### 7. 作用域、名称与持久身份

每次迭代都有一个名称隔离的词法作用域帧。在其中定义的网络名局限于本次迭代。重复 `net LINK: ...` 不得仅因拼写相同而合并不同迭代的网络。同一次迭代内重复声明 LINK，保留通常的同名网络行为。与父作用域网络的连接，通过显式共享物理引脚实现，包括传入既有 fn 辅助函数的引脚，不能因意外复用其显示名称而发生。循环局部网络名不能在循环外引用；需要从外部寻址的数组应在循环外声明，并通过其引脚连接。

现有数组身份保持不变：无论哪些循环操作它，`Board::leds_3` 始终表示元素 3。循环的拼写、迭代次数或布局公式，不得向已声明元素的路径添加循环段。

对于循环操作直接声明的实例/数组、fn 局部对象和网络，使用由**显式循环标签加整数值**确定的内部迭代帧，绝不能使用源码顺序编号、源码行号、时间或进程计数器。规范拼写如下：

```text
Board::__for_channels_3::r
Board::__for_channels_3::caps_0     # element 0 of a loop-local array
Board::__for_decoupling_3::__fn0_decouple::c
Board::__for_links_3::LINK
Board::__for_links_neg1::LINK       # iteration value -1
```

每个循环都必须有标签，包括仅连线或仅布局的循环。循环标签在所属 design/fn 或迭代体内必须唯一；检查这一唯一性时，layout 块不形成独立作用域。每个嵌套循环帧在父路径上继续扩展。复用 fn 定义时，同样的标签分别位于各自既有的调用路径下。带符号索引的规范文本为：非负值使用无符号十进制，负值使用 `neg` 后接其绝对值；这一后缀与保留的 `__for_` 名称族结合标识符标签，构成单射编码。用户代码不能声明内部 `__for_` 名称，也不能通过 Instance/Pin 表达式进入循环内部寻址。

每次迭代都有自己的 fn 调用和匿名网络计数器；进入迭代不消耗父作用域的旧有计数器。本次迭代内部的嵌套 fn 调用，保留现有的递归 fn 计数约定。循环外声明的数组永远不进入这一命名帧。

**调整两个不同标签循环的顺序，或插入一个带新标签的循环，不得重新分配保留下来的循环对象的身份。** 扩大区间时，保留下来的整数值帧保持不变。重命名标签是显式的身份修改，在 lock 中体现为旧/新路径。重复标签使用 E201，不能据此自动发明编号后缀。

这不重新设计 RFC-006 继承下来的 fn 调用身份：修改或调整同一次迭代*内部*的调用顺序，仍可能让相同的顺序编号 fn 路径用于不同目的。仅凭 lock 差异不能证明语义身份得到保留；还必须审查连接关系/part/布局差异。不能承诺自动检测任意意图变化。新增循环层自身不得再引入一层基于位置的身份风险。如果团队以后需要在单独调整辅助函数调用顺序时保持稳定身份，必须另行提出明确的 fn 调用身份提案。

循环/容器自身没有位号或 BOM 行。所有真实的 fn 局部元件仍需绑定 part、获得普通位号，并进入制造输出。重复调用带有硬编码 `#[designator("C1")]` 的辅助函数，必须被现有的重复位号覆盖检查拒绝并报错，绝不能自动生成新的位号覆盖。

### 8. 在明确的绑定环境中检查，再物化对象

扩展共享的声明验证器，使其能够在新 const/表达式/for 构造出现的任何位置检查这些构造，包括未使用的定义和零次迭代的循环体。使用与定义体内普通语句相同且适用的声明检查，验证符号/种类解析、合法词法位置、操作数类型、成员名称和泛型实参结构。新增常量、绑定变量、标签及其依赖环均进行静态检查。`for empty: n in 0..0 { net _: missing.P; }` 不能成为隐藏未知符号的地方。

每个新增 for 的词法电路体内，共享声明验证器必须检查局部 inst/数组名的重复与遮蔽，以及当前带类型环境中能够判定的全部单位、trait 约束和 Pin/Instance 实参种类要求，包括具名泛型转发。把 Capacitance 参数 C 传给 `SeriesR<C>`，即使位于 `0..0` 也是已知类型错误；其中两个名为 r 的局部声明同样为 E201。这些检查覆盖嵌套新体和调用点的签名/实参，但不特化未进入的被调用方，也不递归加强未改动旧 helper 的内部检查。这是对新构造明确的局部加强，不允许继承旧验证器已知的缺口。

**不能仅因一个新构造引用了旧辅助函数，就加强对该函数的检查。** 所有 fn 定义保留既有声明检查，并扩展这些检查以理解新节点。main 的 `check/bodies.rs` 将部分旧有局部名称重复、环路和布局验证留到实际展开时处理；不能因无关调用方的 const 而沿调用链修补这一缺口。例如，向未调用的 `unused() { old(); }` 添加一个未使用的 const，不得突然启用对整个 old() 内部的新增局部名称重复检查。全面统一这些旧有检查，需要单独声明其兼容性变化。这取代了早先草案中“新特性区域加传递性加强检查”的策略。

在三个定义清楚的环境中使用同一个带类型的求值器：

1. **定义验证：** 泛型参数和循环绑定变量具有已知类型，但可能没有值。对整个定义中的具体子表达式求值，并验证不依赖未知值即可确定的失败。
2. **每次实际的 fn 激活：** 绑定实际实参/默认值后，在该替换环境下验证整个定义体，包括嵌套的空循环，再创建其对象。仅依赖这些已绑定参数的值，此时成为具体值。不能仅依据区间语法就绑定循环变量。
3. **每次实际迭代：** 绑定本次迭代的整数，验证循环体中此时已具备具体值的表达式，再贡献相应操作。嵌套循环和实际辅助函数调用重复这一过程。

已知除数为零时，即使分子尚不确定，也已经构成不依赖未知操作数即可确定的失败：空循环中的 `i / 0` 必须被拒绝。`1 / i` 则等待真实的 i 值。不得依赖代数化简为未知操作数推造值。验证常量依赖时，不物化假设的实例或未进入的迭代。

如果 `f<const N: Int>` 内含 `for empty: i in 0..0 { const BAD: Int = 1 / N }`，调用 `f::<0>()` 会在环境 2 失败。相比之下，`for none: i in 0..0 { f::<0>(); }` 没有实际激活 f：检查调用签名/实参表达式，但不对被调用方依赖具体值的检查义务进行特化。同一个空循环中的 `f::<1 / 0>()`，仍会因其自身的实参表达式而失败。因此，把计算提取到一个被跳过的辅助函数中，可能推迟依赖具体值的检查；必须明确这一边界，不能承诺所有不可达计算都会求值。

空循环不创建元件、引脚、网络或放置。不要求证明所有可能泛型实参下的普遍定理；每个实际实例化都接受检查。声明/替换验证不是生成的 fn 调用，也不分配动态循环帧。

展开之后，在既有阶段执行通常的引脚义务检查、网络合并、part 绑定、位号分配和残余 DRC。求值后的索引错误定位到原始源码表达式，并给出合法长度和迭代值。循环生成对象上的下游 DRC 和 part 错误，也必须保留原始源码位置和展开来源。

### 9. 确定性的工作量限制

有限语法仍可能要求生成大得不切实际的电路板。**在物化任何实例或工作项之前**，遍历所选 design 及其在语法上引用的 fn 定义，以选择预算模式。这是使用已访问集合的有限引用遍历，忽略循环次数和 const 是否实际使用，也不对被调用方特化。如果可达语法中包含 const 声明、const Int 泛型参数、for 语句、`.len` 或本 RFC 允许的算术表达式，就启用预算。仅有既有字面量和普通的具名单位参数转发，不会启用预算。使用 Int 默认值的调用，仍会到达 Int 参数声明，因此启用预算。

因此，所选 design 中未使用的 const、空循环，以及空循环内对辅助函数的引用，都可以启用预算；无关且未调用的定义不能。把 `[T; 10]` 改成 `[T; 5 + 5]` 也可能启用预算。这是**显式的兼容性代价**：原本完全相同但规模超限的旧设计，采用任意 M2 语法后都可能开始失败。这不是隐蔽且依赖优化器的“实际使用”判断。引用遍历只选择是否计量，不按第 8 节沿引用关系加强旧有静态检查。

启用后，计量**整个所选 design 的实际展开**，包括此前出现的旧语句，而不仅是源码上位于 for 内部的语句。所选引用图完全使用旧语法时，保留原先行为。调整源码顺序或对常量死代码进行消除，不能关闭这一模式。

- 最多累计**进入 100,000 次循环迭代**，跨嵌套和实际调用累加。
- 最多生成 **1,000,000 个工作项**，按下述语义事件计数。
- 最多存在 **64 个活动循环帧**，包括通过调用进入的循环。这不是对仅由旧 fn 组成的组合新增深度限制。

以下每项计一个工作项：物化的每个真实物理实例（标量或任意数组元素，包括旧辅助函数内的字面长度数组）、每次实际 fn 调用、每条展开后的用户编写 net/nc/place 语句、区间/列表展开后的每个用户编写 net/nc 成员。此外，每个展开后的布局约束声明（`net_class`、`diff_pair`、`length_match` 及其他已允许的约束形式）、其中每个用户编写的网络引用、每个解析后的物理属性记录，以及该记录中每个用户编写的实例/引脚目标，也各计一个工作项。差分对的 physics 方括号，除约束声明外，还贡献一个物理属性记录。必须在追加/物化相应数据之前计入工作量，包括推迟处理的布局工作。一个约束内部的单位值/标量不单独计为对象。这能限制仅按实例计预算时会漏掉的辅助函数约束放大。

数组本体、layout 块、循环头和 const 声明，不另外增加工作项。用户编写的重复成员/引用在去重前计数。递归贡献的工作项，在引发它们的调用之外另外计入工作量。保留现有的语句体遍历规则（声明先于操作）；操作内部使用源码顺序和迭代的字典序，成员/引用列表使用编写顺序，以保证第一个超预算位置是确定的。

示例：预先声明两个单引脚实例，一个循环执行两次、每次生成一条单成员 nc，另一个循环执行两次、每次生成一条 place，总计 **4 次迭代、8 个工作项**：2 个实例 + 2 条 nc 语句 + 2 个成员 + 2 条放置。常量是否已折叠或缓存，不影响计数。循环调用一个包含 10,000 个字面长度数组实例的辅助函数时，必须在分配前计入全部 10,000 个实例，不能只计一次调用。

不存在依赖优化器的表达式指令配额。表达式语言没有调用或递归；常量依赖环会被拒绝。在每个定义/替换/迭代验证环境内，记忆化常量依赖求值，以避免指数级重复计算；验证与实际生成保持区分。纯子表达式优化不能改变溢出/精度判定、预算启用条件或工作项数量。未使用定义的静态验证，不消耗所选 design 的生成预算；也不得物化动态循环或假设的数组。这些限制约束的是被计数的展开事件，不涵盖源码解析、旧编译器所有可能的资源使用，或所有下游输出成本。

尽可能在批量分配之前计算长度/数量，并使用带溢出检查的计数器；外层循环为空时，不得物化其内层乘积。超过任何限制都必须是确定性的硬错误，指出数量、限制及原始展开位置。绝不能输出截断的网表，也不能把部分设计标记为通过。数量/限制属于语言与编译器契约，不是根据宿主机内存估算的阈值或超时；变更它们必须显式修改规范并随版本发布。构建失败时，保留现有的产物所有权/失败策略，不发布新的成功构建结果。

### 10. 诊断与词法兼容性

在语义适用时复用既有错误：E201 名称冲突、E202 已解析索引越界、E211 非法数组形式/长度、E401 泛型实参数量、E403 trait 约束、E110/E111 物理单位不匹配/缺少单位、E112/E113 单位泛型实参，以及现有的放置/DRC 错误。新的泛型标记用于不支持它的声明种类时，使用 E406。不暗中改变任何错误码的用途。运算符值域失败使用 E1401；使用表达式的字段发生物理单位不匹配时，仍使用既有 E110/E111 或泛型 E112/E113。需要 Int 却得到 Length 表达式时，使用 E1401。新支持的负 Int 表达式，可以进入 E202/E211 边界检查，而不再触发旧的词法 E102；必须记录这一有意的诊断细化，同时对仍不接受 Int 的裸数字使用位置保留负数 E102。

提议新增以下错误码段，待接受时集中分配：

| 候选错误码 | 失败类型 |
| --- | --- |
| E1401 | 需要编译期 Int/Length 或受支持的操作数配对；数字非整数、种类错误或属性不受支持 |
| E1402 | 整数/Length 表达式溢出，或 Length 除法无法精确表示 |
| E1403 | 除法/取余的除数为零 |
| E1404 | for 区间逆序 |
| E1405 | 超过确定性的展开预算/深度限制 |
| E1406 | 此循环或表达式位置不允许该声明/操作 |
| E1407 | 常量/数组长度依赖成环，指出完整环路 |

主定位范围是原始源码中导致失败的最小构造。对于依赖展开结果的错误，**主消息**必须包含被违反的约束、具体失败值/合法边界，以及能区分本次激活的简短路径和相关绑定，例如 `Board::__for_links_9, N = 10, n = 9`。即使使用方只显示错误码、消息和主定位范围，关键上下文也必须保留下来。辅助标签补充外围调用位置、循环头，以及确定边界的声明位置。保留 RFC-010 的 schema_version 1 和既有 message/secondary/help 字段。展开错误的内部去重键必须包含展开帧，不能仅因源码范围相同，就悄悄合并两个不同失败迭代。不得引入隐蔽的诊断截断。

求值器的 Int 值域，不能削弱在 Voltage 或 Length 位置拒绝裸数字的规则。`rotate` 仍是一个独立、既有的整数值使用位置，不是物理单位强制转换。

词法处理需要有针对性的兼容性检查：`for` 已经是 `impl Trait for Device` 使用的 token；`const` 和 `in` 只在新增语法位置具有上下文含义，不是全局保留标识符。引入算术标点并解析一元正负号，同时保留旧的带符号 Length/Temperature 值，以及对不允许负值的物理单位拒绝负值的行为。特别是，普通的运算符遗漏不得变成隐式乘法。

保留当前单位后缀的最大匹配规则：**`10%` 是 Tolerance 字面量；`10 % 3` 使用取余运算**。`10%3` 必须被拒绝，不能根据期望类型重新解释单位字面量；fmt 始终在二元运算符两侧放置空格。为 `n-1`、`n - 1`、`-1mm`、`0..10`、`0..=9`、`//` 注释和带符号字面量诊断增加显式测试。不允许依赖符号表的分词或无界前瞻。

## 类型系统优先检验

本 RFC 不增加 rule/DRC 检查。单位替换和 trait、Pin/Instance 要求继续是类型义务。Int 值域/索引/溢出检查和有限生成上限是编译期展开义务。required pin 穷尽性是结构义务，在最终组装后检查，因为此时才知道调用者的贡献。已有整体电气检查继续属于残余 DRC。

保持保证的标准是具体的：每个生成实例携带的已解析 device、spec、引脚角色/义务、trait 绑定及最终 part 要求，都与等价手写实例相同。泛型或重复构造不能把检查失败换成未检查占位对象、消除 required pin，或把缺失数据视为成功。编辑器可以按既有错误状态保留部分模型，但它不是成功构建。

必须有三组配对失败探针：RC 参数的错误单位（也覆盖嵌套转发）；类型为 Int 但越界的 LED 引用；实际生成通道中缺失的 required 连接。再增加第四组故意串接错误通道但仍类型正确的探针：拓扑对照必须发现差异，同时不能声称语言能够推断意图。这使例子与判定阶梯挂钩，而不只是统计生成了多少对象。

## 概念影响与显式修订

永久新增的能力是**通过有界编译期求值进行带类型的参数化电路构造**。其概念成本是纯值与构造效果的区别，以及隔离名称的迭代帧，不是第二套器件或连接模型。for 是使用这一能力的位置之一；数组选择器和 const 泛型实参是另外的位置。不能创建独立的“数组算术”“布局算术”和“模块可编程”引擎。

评审指南中的 P01–P10 是既有原则的追溯编号，不增加规范权威：

| 原则 | 在本 RFC 中的具体后果 |
| --- | --- |
| P01/P02：承诺可检查、信息充分时尽早检查 | 定义/带类型绑定检查、具体索引验证，最后检查引脚义务；必须有配对失败例 |
| P03/P05：共同语义、显式来源 | 复用 inst/fn/net 和泛型绑定；显式共享引脚才合并网络，局部同名不合并 |
| P04/P06：固定输入、持久身份 | 纯求值、精确锁定依赖、具名迭代路径；重复构建字节与编辑后身份分别测试 |
| P07/P08：物理责任、工具 | 每个生成元件保留在流水线中；格式化、诊断、LSP 和符号文档与功能一起交付 |
| P09/P10：有限承诺、显式演进 | 披露意图/模拟/物理边界及暂缓能力；仅经接受流程修订受影响的 Accepted 契约 |

| 既有契约 | 必须显式作出的修订 / 保留的边界 |
| --- | --- |
| RFC-001 单位 | Int 位于物理单位集合之外；精确 Length 运算复用其表示方式和零强制转换规则。必须显式规定：在新增允许整数的位置，E102 不再拒绝负 Int 字面量 |
| RFC-007 泛型 | 同时修订“不允许非单位 const 泛型”和“Length 实参仅限字面量/参数”的限制。为 fn 增加 `const N: Int`，并通过共享替换机制支持 Length 实参表达式；默认值仍仅限字面量 |
| RFC-024 数组 | 将仅限字面量的数量/索引替换为经过检查的 Int 表达式；保留长度为正、元素真实存在、批量展开仅用于网络成员的规则 |
| RFC-032 subdesign | 保留端口类型、层级与布局契约；按前述事项，在接受前明确共享数量/索引支持、重复、所属关系与预算遍历 |
| RFC-006 fn | 在迭代帧中复用 inst 与 fn 构造，共享参数绑定和来源信息；保留无环性、真实局部元件及旧无循环行为 |
| RFC-005 身份 | 既有数组路径和分配器不变；规定循环生成的路径，并披露编辑引起的身份变化 |
| RFC-009/010/011/014 工具 | 规范格式化、源码定位/来源信息、已登记错误码和 LSP 理解能力必须一同交付 |
| 包 API 文档契约（`docs/apidocs.md`） | 显式为符号化定义体/签名表示升级版本；见“工具与运行”。诊断 JSON 保持版本 1 |
| RFC-013/020/025/026 布局 | 经既有几何规则求值位置/旋转；显式将 place 扩展到可见的 design 所属循环局部实例。仍排除访问 fn 内部及 pad 表达式，不增加布线或电气推断 |
| RFC-029/030 依赖 | 离线 check/build 与精确锁定的包保持不变；表达式不能查询 registry/网络状态 |

这些能力属于 cohdl.dev 的语言/编译器职责。cohdl.ai 可以生成源码并使用判定结果；它不得提供第二套预处理器、私自解释循环，或选择不同的算术规则/限制。Konnect/KiCad 操作编译器输出，并执行它们通常的物理检查。

## 一致性矩阵中的本提案行

| 概念 | 语法 | 验证器（Oracle） | 诊断 | 网表 | 兼容性 | 信任 |
| --- | --- | --- | --- | --- | --- | --- |
| 高 | 高 | 高 | 高 | 高 | 高 | 高 |

- **概念：** 用数量相关的真实数组和有限迭代，说明 Int/const 的必要性。显式排除运行时值和物理规格算术。保持 module、fn、Instance 和 Net 的含义各自清楚。
- **语法：** 一张优先级表和一个表达式 AST；const 泛型扩展既有参数列表。循环区间只有一种形式；批量展开保留其不同的电气含义。上下文拼写避免侵占既有声明名称。
- **验证器：** 静态定义体验证，加上每次实际使用时的具体展开，再进入既有编译流程；不忽略语句、不隐藏未知项、不跳过真实 part。
- **诊断：** 原始源码范围和展开帧，通过现有 check/build JSON 和 LSP 保留下来；必须有负值、空循环和溢出测试。
- **网表：** 循环局部名称不能使同级迭代短接；不能有虚假的循环元件。与手工展开的设计比较图等价性，包括所有引脚、NC 和放置。
- **兼容性：** RFC 之前的有效源码，其黄金基准输出和 design.lock 必须逐字节相同；带符号/单位词法和旧 fn 计数器需要专门的回归覆盖。把源码重构为带标签循环，是设计修改，可能改变作用域内网络/fn 局部名称；不能错误承诺重写前后字节相等。
- **信任：** 违反边界/资源限制时确定性失败，不允许依赖时间的求值或部分成功；同时演示安全重复和明确可见的失败。

这不是一个低影响的解析器便利功能。接受时，必须在同一次设计变更中更新受影响的规范章节和决策记录。实现不能一边依赖修订后的规则，一边声称 RFC-007/024 未发生变化。

## AI 可生成性

作者为循环站点命名，指定有限区间，并写出显式操作。检查器报告具体哪个绑定/索引失败。用数组命名可从外部逐项引用的实例族，用循环局部 inst 创建私有重复元件，用 fn 表达带类型的复用片段，用 for 重复其构造。模型不需要通过字符串生成实例名称，也不需要用外部脚本构造电路图。

核心修复示例很具体：相邻索引越界时，将 `0..leds.len` 改为 `0..(leds.len - 1)`，然后重新运行普通检查。对于另一种索引未越界却拓扑错误的情况，还必须通过应用专用的比较测试捕获；循环支持不会推断用户意图。

## 替代方案

1. **只对预声明数组重复操作。** 用较小的声明范围覆盖 LED 链与网格。具有私有 r/c 的通道需要在循环外声明数组，或仅为创建局部元件而增加 helper。方案可行，但构造的组合性较弱，不再是针对本次多元件/嵌套场景的推荐。
2. **通过既有 inst/fn、共用表达式和具名 for 进行带类型的有限构造（推荐）。** 无需新增可返回电路对象、可变状态或另一套连接 API，即可覆盖三个场景。代价是局部声明作用域、实例身份和如实表达符号体的 API 文档。数组与局部实例具有不同寻址用途，不是任意语法限制。
3. **现在就加入宿主语言解释器或完整通用语言。** 带来丰富计算/分支，但引入或要求副作用、终止性、值类型、打包与错误来源契约。tscircuit 为组合便利性提供有用证据，不能通过类比证明满足这些 CoHDL 义务。一般公式/配置/选型仍可作为该模型的独立扩展规定。

更小的实现可以暂缓常量/数量泛型，但不能据此声称完成了参数化库场景。共用一个求值器不要求现在交付全部未来值类型或控制构造。局部常量避免新增导出符号/registry 语义；const 标记避免侵占名为 Int 的 trait。强制循环标签避免按源码顺序分配身份：交换两个同形循环，不得重新分配存续元件。邻接算术特例、布局与接线分别求值，以及字符串生成标识符，都会增加语义，却不能更好地服务这些场景。

## 兼容性

本提案显式修订已接受规范中的排除项，不假装此前所有文字仍然具有规范效力。不替换任何既有数组拼写。不使用任何新构造的既有有效源码，必须保留判定、design.lock 和每一个输出字节。此前无效、现在允许作为整数表达式的语法，遵循其新规定的诊断；这不是承诺继续拒绝新特性。除循环正常路径样例外，还必须回归覆盖引脚编号、带符号物理字面量、名为 Int 的 trait 参数、旧物理值使用位置的负数错误，以及容差 `%` 字面量。

采用循环可能重命名匿名/局部网络或 fn 局部路径。应保留拓扑和既有数组身份，检查 lock 差异，并核对协调布局映射。不自动迁移已布线电路板，也不使用 fmt 重写所有源码。纯常量算术不引入不确定的依赖输入。

## 工具与运行

以下是建议的实现衔接点，不构成实现授权：一个表达式 AST/求值器；共享泛型替换环境增加 Int；选择器 AST 在能够具体解析前保留表达式；定义体/layout 遍历器保留循环和 const 节点，不通过文本替换源码实现。不能让词法迭代帧改变既有 design 层放置上下文。在下游诊断共享的已检查数据中，保留原始源码范围和展开来源。

`cohdl fmt` 只格式化，不展开或常量折叠用户编写的源码。除幂等性外，还要验证语义保持：从 `(n + 1) * 2` 去掉括号，可能得到一个不同但仍不越界的电路。LSP 识别常量、循环绑定变量和数组声明；只有单个实例化足以确定长度/值时，才显示具体值。泛型/循环引用可能有多个值，不能任取一个并显示为普遍成立的值。不支持 relatedInformation 的 LSP 客户端，以及 Explorer 现有的仅消息诊断投影，仍应收到第 10 节规定的关键展开上下文。Explorer 使用同一套展开实例和原始源码映射；不存在第二套 JS 展开器。

**包 API 文档需要显式的版本化契约。** 基准版本的 `body_summary` 只输出平铺的 insts/calls/nets 和数值数组长度；它无法通过报告零个网络或编造长度，来如实描述一个尚未实例化的 N 元素循环。提议的最小方案如下：

- 需要 M2 签名/定义体表示的文档，使用包 API 文档 `schema_version: 2`；输出项不需要新表示的文档继续使用版本 1。这与诊断 JSON 无关，后者保持版本 1。既有版本 1 字段的语义不变。
- 在版本 2 中，Int 泛型在既有泛型描述对象中使用 `bound: {"const": "Int"}`；`name` 和以字面量文本表示的 `default` 保持原有含义。单位/trait 描述保留既有形式。
- 每个自身签名或词法体使用 M2 的 fn/design 项，都在以其种类命名的载荷中提供 `body_source` 字符串。这是采用规范 CoHDL 格式、包含花括号的完整定义体，保留常量、符号化长度、嵌套、标签和表达式。省略该项旧有的 insts/calls/nets 摘要字段，不能把不完整的直接语句数量当作总数。其他项字段保持既有含义。使用同一个格式化器；不要另建定义体渲染器，也不要暴露一套相互竞争的可执行 JSON 语言。
- 既有泛型实参字符串列表中的 M2 值表达式，使用用户编写表达式的规范文本，而不是猜测的值。推导出的具体 spec 值使用第 2 节的值文本规则。只要输出的本地项或 foreign 项需要上述任一形式，整个文档就是版本 2。
- 在声称支持版本 2 上传之前，registry 的上传验证/存储和查看器必须同时支持两个版本。尤其要更新现有只接受版本 1 的外层结构验证器。将 body_source 作为转义后的源码文本呈现，并识别 fn/design 载荷中的 const Int；不要对循环求值或显示虚构的展开数量。不支持的版本必须产生明确的格式不受支持结果，绝不能自动降级为空摘要。

在获接受后的实现中，更新 `docs/apidocs.md` 以及编译器→registry→查看器契约测试。公开的版本 2 形式属于范围选择的一部分，不是“自动获得的增量兼容”。文档 sidecar 继续独立于包 tar/哈希身份；现有尽力而为的文档上传，不得把成功的包发布变成失败的包发布。准确的签名/源码视图之外的查看器展示，可以另行跟进。

不需要新增 CLI 命令、插件、网络调用、JSON 诊断 schema 或制造输出格式。变更不得增加编译器依赖，也不得让无序 map 的迭代顺序泄漏到输出。导出的组合层级树不是这一候选迭代机制的前提。

## 教学成本

先把循环标签解释为持久的站点名称，再讲有限的左闭右开区间、单个网络内批量展开与跨多个网络迭代的区别、精确结构算术与物理单位的区别，以及循环局部作用域。随后说明既有 fn 组合与迭代怎样贡献普通的、经过检查的对象。从一个 LED、两个 LED 开始，再到十个；与显式网络和位置对照。

## 失败模式

验收表覆盖差一错误、静默短接、真实元件消失、默认值作用域错误、隐藏的空循环体错误，以及资源耗尽。还要防止错误承诺：生成成功不等于电气仿真；间距可计算不代表满足净距；数值参数 N 不会选择转换器；E140x 错误码段不能替代既有 part/引脚/DRC 检查。

## 迁移路径与一致性门槛

接受之前，按笔记 1–8 审查本草案，解决具体范围决策，分配 RFC/错误码，记录决策，并更新笔记 10 及 RFC-007/024/032 的交叉引用。须先完成前述组合修订；现有仅考虑 fn 的细节尚未满足这一条件。这包括新的默认值/上下文限制和实际的循环身份保证，不只是示例语法。

接受之后，实现表达式/类型和展开语义及其诊断/测试，再更新 fmt/LSP/docs/Explorer 使用方，并迁移一个参考样例。这些是实现同一个一致契约的步骤，不是允许交付只做部分检查的循环。保留手工展开的判定基准。通用电气计算/选型继续作为独立的 M3 提案；循环生成的设计以后可以用作 M3/M4 验收案例。

## 决定

**Proposed — 已校正 main 依据；接受前仍须完成组合修订。** 不声明 Accepted 状态、编译器实现或硬件验证。推荐有限构造范围，包括迭代局部直接 inst、Int/Length 求值、局部常量、fn 数量参数、具名循环及明确受限的放置扩展。接受时还必须决定身份契约、整板预算启用和包文档 v2 契约，并同步更新受影响规范。暂缓的配置/公式/电气契约仍是明确列出的能力，分别承担后续义务，不是本 RFC 隐含提供的功能。
