# RFC 草案：参数化电路构造与有界编译期求值（M2）

## 状态与已选范围

**草案 / Proposed — 用户于 2026-09-12 选定候选 A。尚未 Accepted，尚未实现。** 正式 RFC 编号尚未分配。本轮以英文为工作依据；中文全文于 2026-09-12 同步。若表述存在分歧，以英文为准。范围决定记录在 `docs/proposals/decisions/2026-09-12-m2-scope-a.md`，不替代语言的正式接受。此前的比较稿和实施清单已归档。

**本轮 M2 已选范围：候选 A。** 增加有界、带类型的计算，以及针对具名物理/subdesign 对象的操作循环，保留普通的带构造效果的 fn 调用。数量、索引和放置可编程；真实元件在普通电路体/数组中声明，或由调用的 fn 片段创建。**循环体内直接声明 inst/subdesign（候选 B）延后。** 下文规定 A 的契约，B 仅作为延后的比较材料。标签和 fan-out 写法仍需在接受前分别决定。

非规范性的 `docs/language-design-principles.md` 提供评审问题，不构成第二份语言规范。接受本提案仍需决策记录，并同步修改文档 10 与受影响的 RFC。提议语法和未来测试不是实现证据。

## 约束性基线与职责划分

2026-09-10 已拉取 main，提交为 `0e3d7705ab393a5c64c20836540ad1bc2e49898e`。[RFC-032](https://github.com/conol-ai/cohdl/blob/0e3d7705ab393a5c64c20836540ad1bc2e49898e/docs/design/rfc-032-subdesign.md) 已于 2026-09-08 Accepted，并纳入[文档 10](https://github.com/conol-ai/cohdl/blob/0e3d7705ab393a5c64c20836540ad1bc2e49898e/docs/design/10-language-specification.md)。遵循 AGENTS.md 的权威顺序及[实现偏离记录](https://github.com/conol-ai/cohdl/blob/0e3d7705ab393a5c64c20836540ad1bc2e49898e/docs/compliance-report.md)。本分支已关闭的历史 harness 提案在另一个文件中使用相同编号，它不提供语言层面的规范依据。此前因此排除 subdesign，是编写错误，现已撤回。

| 构造 | 保留的既有职责或提议职责 |
| --- | --- |
| `module` | RFC-016 已有的名称、导入与可见性 |
| `subdesign` | 已有的 Pin 端口、具名层级、共享泛型替换、数组、嵌套组合，以及支持整组放置和内部器件覆盖的默认相对布局 |
| 物理实例数组 | 已有的真实元件具名集合；M2 让长度与选择器可计算 |
| subdesign 数组 | 已有的逻辑组合节点具名集合，节点内含真实子对象；M2 使用同一个数量/索引求值器 |
| `fn` | 已有的带构造效果的内联电路片段，接收 Pin/Instance 实参；局部对象是真实元件，但没有可供外部放置的接口 |
| `for` | 提议重复执行该上下文允许的语句；引入迭代的词法作用域，不引入端口接口或坐标系 |
| 纯表达式 | 提议无电路效果、无 I/O 的 Int/Length 计算；返回值的纯 fn 模型不在本次修订范围内 |

跨越 subdesign 边界的电气访问仍通过端口。只有放置操作可以深入引用内部实例。subdesign 不是物理 Instance，没有 part、位号或 BOM 行，不能满足 Instance 类型的 fn 形参。物理引脚保留最终组装义务；required 端口还遵守现有的“连接到节点外部”检查。对端口使用 `nc` 仍报 E1306，在 fn 内使用 subdesign 仍报 E1307，即使通过循环也不例外。A 保留 fn 现有的器件构造能力。

**已知不一致：** RFC-032 / 文档 10 将 fn 描述为同包复用，但 RFC-016 的解析机制和现有 `pub fn` 支持跨包调用。对外保留的接口与布局访问才是可靠的区别；相互冲突的包边界表述需要通过治理修正。RFC-032 还要求检查后的 IR 保留层级，而当前公共 `src/ir.rs` 暴露平面的物理设计，展开器在内部保留 subdesign 节点。仅有子对象路径，不能证明已有完整的公共层级模型或完整 Explorer 支持。本 RFC 不撤销 RFC-032，也不将实现缺口当作省略 subdesign 的许可。

当前任务是完成和审查本 RFC 的能力模型、带类型语义及三个场景。按用户 2026-09-12 的要求，语法比较作为后续材料放在附录 A，声明验证器的实现及兼容性证据作为后续材料放在附录 B。正文保留拟议写法和检查义务，以便完整评审。两个附录都不表示在本次 RFC 编辑任务中启动原型或审计。

## 问题

CoHDL 已能描述器件、物理实例、连接、可复用 fn 定义，以及 Accepted 的 subdesign 组合。RFC-024 加入使用字面量数量和索引的 `[Device; N]`，但明确将依赖数量的接线和放置留给手工完成。一个板型系列还需要重复整个通道：实例化其中的电阻、电容，连接两者，再把该通道组合进另一个可复用定义。

只加入 `for` 的 RFC 无法回答核心问题：程序能计算什么、构造什么，值与物理对象如何区分，生成后仍执行哪些检查？用户需要改变通道数量或复用电路，同时保留单位安全、引脚义务、稳定的物理身份，以及编译器解释失败原因的能力。

预期作者包括生成/修复 `.cohdl` 的 AI、审查结果设计的人，以及组合参数化电路的库作者。下文三个验收场景是语言契约测试，不表示 LED 链或 RC 网络已经成为经过验证的硬件产品。

## 目标

1. 独立于某一种循环写法定义 CoHDL 可编程能力，明确输入、值域、构造效果与检查阶段。
2. 通过共享机制表达级联、重复的多器件通道，以及嵌套的参数化 fn/subdesign 组合。
3. 保留构造前的单位、trait、参数种类检查，以及组装后每个真实实例的连接义务。
4. 确定性地拒绝具体值错误和过量展开，保留源码表达式，并区分调用/迭代上下文。
5. 保留已有数组身份和旧输出，规定新生成对象在编辑中的稳定性边界。
6. 为 check/build、fmt、LSP、docs 和 Explorer 提供一套语义；cohdl.ai 消费它，不另行实现。

这些目标服务于产品宪章的前五项优先级：正确性/机器可检验性、AI 可生成性、人类可审查性、可组合性和忠实输出。减少输入是收益，但不能据此证明正确。

## 能力模型：CoHDL 应具备什么可编程能力

**CoHDL 的可编程能力，是利用显式参数和经过检查的编译期计算，构造有限的电气设计，并让其中的实例、连接和已声明约束继续接受普通编译器契约的检查。** 这是设计时计算；循环或变量不会成为在制成板上运行的固件。

完整能力模型与本次 M2 提议交付的范围刻意分开：

| 能力 | 对 CoHDL 的含义 | 本次 M2 提议 / 剩余工作 |
| --- | --- | --- |
| 参数与值计算 | 从显式输入推导设计数据 | 增加 Int/Length 表达式、局部常量和 fn/subdesign 数量参数；保留其他现有单位字面量/参数转发。一般量纲公式和返回值函数需要后续契约 |
| 电路构造 | 根据这些数据创建真实实例和显式连接 | A 使用普通电路体声明、物理/subdesign 数组及带构造效果的 fn 调用；循环重复允许的操作。排除循环体内直接 inst/subdesign 声明及源码字符串生成 |
| 重复与组合 | 构造 N 路通道，并在另一个定义中复用 | 同时推广物理数组与 subdesign 数组；有限 for 与现有 fn/subdesign、共享泛型绑定组合。fn 保留构造效果；循环标签不是返回的电路对象 |
| 配置 | 从声明的备选项中选择电路形式或固定器件 | 保留已有类型实参及 RFC-008 结构变体；零次或多次 helper 调用提供数量控制的构造。通用 Bool/if、分支选择及分支专属检查延后 |
| 领域配方 | 给定电压/电流要求，推导元件参数并选择合适物料 | M3 必须规定量纲公式、适用的器件事实、选型策略和锁定结果；M2 提供组合/数量机制，不提供该求解器 |
| 可检查的电气契约 | 对选定或生成的设计声明并验证义务 | 保留现有单位/trait/引脚检查和恰好四条残余 DRC。M4 必须对额外契约、证据和缺失数据行为分类；这里不承诺任意运行时 assert |

普通参数化 fn 已能转发显式的电阻/电容值。后延一般电气公式，不意味着后延这些已有的带类型值。同样，显式传入固定 part 不等于自动选型。MVP 可以实现该模型的一个有界子集，无须将这个子集称为通用编程语言。

### 值、引用与构造效果

以下三类必须保持区分：

- **值：** Int 数量/索引与物理量。求值产生一个值，不修改电路，不执行 I/O、registry 查询，也不分配物理元件。M2 只扩展 Int 和 Length 的算术。
- **引用：** 物理 Instance/Pin 绑定、合法逻辑端口引用和带索引的数组元素。具名 subdesign 节点与物理 Instance 的种类不同；裸数组和 subdesign 节点都不能冒充 Instance 或 Pin。引用不能相加，不能序列化成生成的标识符，也不能用于读取未声明的电气事实。
- **构造效果：** inst 贡献物理实例；net 贡献连接关系；nc 贡献显式不连接决定；fn 贡献展开后的片段；subdesign 使用点贡献逻辑节点及其真实内容；layout 贡献已有的放置/约束事实。for 重复执行允许的构造效果。const 不创建其中任何一种。

在允许声明的普通电路体内，标量 inst 每次激活创建一个真实实例；数组 inst 创建求值所得正数长度的真实元素。引用同一实例两次不会创建两个元件。调用带构造效果的 fn 两次会创建两套局部元件，不能当作纯计算用记忆化消去。M2 不增加对象返回/集合 API、可变图 API 或隐藏自动接线。具名物理/subdesign 数组提供可从外部寻址的对象集合。A 排除循环体内直接 inst/subdesign 声明；被调用的 fn 片段保留普通声明。

### 检查契约也是能力的一部分

输入带类型，本身不能证明展开得到的电路有效。本 RFC 要求分阶段的契约：

| 阶段 | 可用信息 | 必须履行的义务 |
| --- | --- | --- |
| 定义/类型验证 | 已声明的类型、名称、trait 和具体子表达式 | 解析符号与引脚成员；遵循设计 §8 并受附录 B 的兼容性条件约束，即使定义未使用或体为空，也检查合法参数种类、单位兼容性和新增构造 |
| 绑定与有限展开 | 实际泛型值、数组长度和每次实际进入的循环值 | 检查整数值域、边界、精度、操作上下文与预算；创建避免名称捕获、带来源信息的对象 |
| 最终设计组装 | 全部生成的实例、网络和 nc 决定 | fn/subdesign/循环展开后，执行物理引脚义务和 RFC-032 required 端口检查，保留已有并网/冲突检查 |
| 残余 DRC | 组装后的图与显式建模的电气事实 | 原样执行现有四条规则；结构性的索引/类型错误不变成第五条规则 |
| 构建与投影 | 已检查设计，加上物料、锁和引用资源 | 对每个真实实例执行已有 part/封装/分配/输出契约；不产生虚假的循环 BOM 行，不报告部分成功的 build |

这里是**类型系统优先，而非只靠类型系统**。Int 仍可能越界，类型正确的连接仍可能接错预期通道，通过已有 DRC 也不能证明模拟响应。这三类问题分别需要具体值检查、独立拓扑判定器，或领域/物理证据。Pin 参数并未成为新引入的、以电压为索引的依赖类型。我们不证明每一种可能的 const 泛型实例化都有效：检查每次实际激活，在信息足够时提前拒绝已知必然发生的错误。

## 与 CoHDL 类型系统的关系

### 扩展带类型的构造，保留现有电气模型

M2 扩展语言的编译期值与构造机制，不替换 Device、Part、Trait、Pin 或它们现有的契约。这个区别很重要：为数量加入算术不会创建新的电气单位，重复声明也不会弱化被声明器件的类型。

| 现有机制 | 与 M2 的关系 | 具体验收义务 |
| --- | --- | --- |
| RFC-001 物理单位类型 | 保留所有现有单位身份和零强制转换；增加规定的精确 Length 算术，Int 是独立的结构性值域 | `100nF` 不能绑定 R: Resistance；`10mm + 2` 失败，`10mm + 2 * 1mm` 的类型是 Length |
| RFC-003 trait 满足关系 | 每次具体器件替换仍需满足 impl，并具有有效的 trait 引脚/spec 映射 | 传入一个其他方面有效、但缺少所需 Capacitor impl 的器件，即使通过重复 helper 到达，也会失败 |
| RFC-007 泛型参数 | 通过同一绑定/替换机制向 fn 和 subdesign 增加结构性的 `const N: Int`；保留单位值和 trait 约束的类型参数 | 在嵌套调用中转发 N、R、C，保留各自不同的种类；默认值不抹除预期种类 |
| RFC-024/032 数组 | 共享数量/索引表达式，保留物理元素与逻辑元素的种类区别 | 两者长度都必须为正 Int；选中的物理引脚和 subdesign 端口各自保留义务 |
| RFC-006 fn 与引用绑定 | 复用 Pin/Instance 绑定和带构造效果的片段展开 | Pin 实参引用已有物理引脚或允许的 subdesign 端口；调用两次 helper 创建两套局部对象，不复制传入对象 |
| RFC-002 引脚义务 | 保留最终组装时的穷尽性检查 | 每个实际物理实例及 required subdesign 端口都参与，包括只有在调用者接线完成后才暴露漏接引脚的情况 |
| RFC-004 残余 DRC | 保留现有四条图层面的规则 | 类型不匹配和具体索引错误都不交给新增 DRC 规则处理 |

### 三种泛型输入，一套替换规则

在 `fn bank<const N: Int, R: Resistance, D: Capacitor>(target: D, pin: Pin)` 这样的声明中，N 是结构性整数值，R 是 Resistance 值，D 是受 trait 约束的器件类型。它们不是无类型参数的几种可互换写法。`target` 是按 D 检查的实例引用，`pin` 是引脚引用；两者都不是计算出来的标量。

当前实现通过 `GenericBound::Unit`/`Traits` 和 `GenericValue::Unit`/`Device` 表达已有分类（`src/ast.rs`、`src/check/generics.rs`）。M2 需要独立的 Int 分支，以及能保留类型与源码 span 的默认值/实参表示。不能将 N 编码成假的 UnitValue，不能从字符串推断种类，也不能只为循环增加第二套泛型解析器。这些实现接点解释了机制关系；具体 Rust 枚举分支名称不是公开语言语法。

同样，已有 trait 约束描述器件义务，不描述数量值上的任意谓词。N > 0 在数组长度使用点检查，不会悄然成为新 trait。通用 where 子句、精化类型以及任意整数定理证明器均不属于 M2。

### 类型已知不等于数值已知

绑定泛型 N 之前，编译器可以知道 N 是 Int，却不知道它是 3、0 还是负数。因此可以在类型验证阶段拒绝 `N + 1mm`。`[D; N]` 是否具有有效正长度，要等 N 具体化后检查。同样，`leds[n + 1]` 的索引类型可以正确，却仍在最后一次迭代发生具体边界错误。

数组形状只在这个有限意义上依赖值；M2 不引入通用依赖类型系统、不为所有可能索引提供编译期证明，也不在物理板上执行运行时边界检查。它检查每次实际实例化/迭代，在接受设计前拒绝无效构造。设计 §8 的空循环规则仍拒绝已知不变的错误，但不会为未绑定循环变量编造值。

```cohdl
// Proposed negative example: no concrete value for C is needed to find the unit error.
fn wrong_channel<C: Capacitance>() {
    inst r: SeriesR<C>
}
```

即使未调用，该定义也必须失败，因为 SeriesR 要求 Resistance，而 C 的类型是 Capacitance。空循环调用该 helper 不会掩盖声明错误；直接在循环内写 inst 超出 A 允许的上下文。两种检查都不需要 C 的具体值。依赖未绑定迭代值的除法遵循设计 §8 的延后检查边界。类型信息与值信息的区别，不是允许跳过未使用的体。

### 连接义务在构造后组合

普通 `Pin` 类型确定引用种类，不断言该引脚具有某个运行电压或最大安全电流。这些事实必须来自已有建模的 spec/注解与适用检查，或来自未来电气契约提案。因此，电阻参数的类型不能证明整个 RC 网络具有预期传递函数。

helper 可以只连接调用者拥有器件的一部分。未解决的 required 引脚仍是最终设计的义务；不能提前拒绝，也不能在 helper 返回时丢弃。for 重复的是同一种片段行为。全部真实实例和连接确定后，已有最终组装阶段检查每项义务，保留未提及的 required 引脚、显式 nc 和已连接引脚之间的区别。

构造保持性要求是：在已声明的源码对应关系下，每个生成实例与其显式版本具有相同的已解析器件/spec、trait 角色映射和引脚义务；结果图通过相同的普通检查。这是通过正反例 fixture 验证的实现验收性质，不表示本 RFC 给出了形式化健全性证明。所有这些检查通过时，连接仍可能违背用户意图，所以独立拓扑判定器仍然必要。

### 类型边界决定实现顺序

在接受循环生成对象之前，先实现带类型表达式和共享泛型替换。然后增加新作用域帧的声明验证、具体求值/展开，以及最终图与来源信息集成。只有解析器支持的 for、循环专用的字符串替换阶段，或独立展开数组的编辑器，都无法满足该契约。工具必须像编译器一样区分符号类型、已绑定值和已组装电路。

## 三个场景与完整布局工作流

以下片段使用提议语法和合成器件接口，用于设计比较，不是已执行的 M2 程序。现有手写 fixture 保留各自带日期的证据。绑定真实物料的测试与合成拓扑检查分开，两者都不能证明模拟响应或可制造性。

### LED 级联：在物理数组上计算连接

```cohdl
// Proposed fragment; host and AddressableLED interfaces are supplied by the fixture.
const N: Int = 10
inst leds: [AddressableLED; N]
net VCC [5V]: host.V5, leds[0..=(leds.len - 1)].VDD
net GND [gnd]: host.GND, leds[0..=(leds.len - 1)].GND
net DATA: host.DATA, leds[0].DIN
for links: n in 0..(leds.len - 1) {
    net _: leds[n].DOUT, leds[n + 1].DIN
}
nc: leds[leds.len - 1].DOUT
```

A 无需在循环内直接 inst 即可表达该场景。N = 1/2/10 时分别贡献 0/1/9 条相邻网络。电源 fan-out 创建一条共享网；使用包含末端的端点，是因为沿用既有选择器写法，不是因为一网语义要求这种区间。循环使用半开区间。附录 A.2 记录了写法成本及仍需决定的替代方案。

草案中的 `links` 标签标识生成操作及其来源，不标识 LED 数组、布局组或 subdesign。LED 保留已有的数组身份。`n + 1` 即使是 Int，越界仍失败；删除供电连接仍会暴露 required 物理引脚。显式将供电引脚标为 nc 满足现有结构处置规则，但不能证明适合上电工作。

### RC 通道：比较完整的板级设计任务

先表达已有的可复用单元。只有后面的 const、可计算长度/索引和循环属于 M2 新增内容：

```cohdl
subdesign RcChannel<R: Resistance, C: Capacitance> {
    ports {
        required IN: Pin
        required OUT: Pin
        required GND: Pin
    }
    inst r: SeriesR<R>
    inst c: ShuntC<C>
    net _: IN, r.A
    net _: OUT, r.B, c.A
    net _: GND, c.B
    layout {
        place r at (0mm, 0mm)
        place c at (3mm, 0mm)
    }
}

design FilterBoard {
    const N: Int = 10
    inst inputs: [SignalSource; N]
    inst outputs: [SignalSink; N]
    inst ground: Ground
    subdesign channels: [RcChannel<1kohm, 100nF>; N]

    for wiring: i in 0..channels.len {
        net _: inputs[i].OUT, channels[i].IN
        net _: channels[i].OUT, outputs[i].IN
        net GND [gnd]: ground.GND, channels[i].GND
    }

    layout {
        for placement: i in 0..channels.len {
            place channels[i] at (10mm + i * 8mm, 15mm)
            place inputs[i] at (10mm + i * 8mm, 5mm)
            place outputs[i] at (10mm + i * 8mm, 25mm)
        }
        place ground at (0mm, 15mm)
        place channels[6].c at (62mm, 17mm)
    }
}
```

这是 A 选用的 RC 组织方式。它含 2N 个无源件、2N 个信号接口及一个地接口：共 4N+1 个物理实例和 2N+1 个电气网络等价类。容器和虚拟端口数量不等于元件/BOM 数量。地网通过显式共享连接合并；打印名称相同不构成新的跨边界连接规则。错误 R/C 单位、缺失 required 端口、内部物理引脚漏接及仍类型正确的通道误连，需要分别设置失败探针。

评审工作流是：**定义 → 实例化十路 → 端口接线 → 独立布局 → 调整第七路电容 → 扩为十二路**。N = 10 时，第 6 号通道的默认电容原点应为 (61mm, 15mm)，显式覆盖后为 (62mm, 17mm)。N = 12 时，必须保留该覆盖和先前所有通道原点。从十路锁文件开始，仍存在的 `FilterBoard::channels_0::r` 至 `channels_9::c` 保持路径、位号和预期端子关系。比较限制到存续端点的连接关系：共享地等价类可以合法增加新端点。还要验证新增的两组 R/C、新接口实例，以及完整的 part/BOM 覆盖。不能仅因为循环对既有通道接线或放置，就向该通道路径插入循环片段。

延后的 B 方案可以把 r/c 声明直接放进循环，但其私有局部对象缺少这里独立的外部覆盖接口。把放置移进构造循环，不满足独立布局编辑任务。因此本轮 M2 选择具名 subdesign。历史直接局部构造例子保留为延后的研究，不是 A 的可执行样例或验收要求。

### 嵌套复用：通过逻辑边界与 helper 共享替换

```cohdl
fn join(src: Pin, dst: Pin) {
    net _: src, dst
}

subdesign FilterBank<const N: Int, R: Resistance, C: Capacitance> {
    ports {
        required IN: Pin
        required GND: Pin
    }
    inst receivers: [SignalSink; N]
    subdesign channels: [RcChannel<R, C>; N]
    for wiring: i in 0..N {
        join(IN, channels[i].IN)
        join(channels[i].OUT, receivers[i].IN)
        net _: GND, channels[i].GND
    }
    layout {
        for placement: i in 0..N {
            place channels[i] at (i * 8mm, 0mm)
            place receivers[i] at (i * 8mm, 10mm)
        }
    }
}

// Proposed fragment in a design with declared source and ground interfaces:
subdesign bank: FilterBank<3, 1kohm, 100nF> {
    IN: source.OUT, GND: ground.GND,
}
layout {
    place bank at (10mm, 15mm)
    place bank.channels[1].c at (22mm, 17mm)
}
```

A 通过共享泛型替换传递 N/R/C，在 join 中使用既有 Pin 绑定，并保留嵌套相对布局和板级覆盖路径。N = 3 时，该共享输入场景含 11 个物理实例、五个电气网络等价类，包括信号源与地。它与独立输入 RC 工作流并非拓扑等价。每种生成写法都应在相同接口、器件参数和布局要求下，与各自的显式参考比较。

fn 保留构造效果：另加回归，重复调用当前去耦 helper，证明每次调用产生一颗真实电容，物理引脚属性目标合法，物料义务不变。整个 subdesign 仍不能替代 Instance 实参，逻辑端口也不会自动成为合法的物理属性目标。将所有 fn 改成纯函数，需要另一份迁移提案。

| 维度 | 已选 A：操作＋既有组合 | 延后 B：增加循环局部构造 |

## 设计

### 1. 含义：有限构造，随后执行已有检查

三个场景定义构造效果。for 对静态有限区间中的每个整数展开允许的操作：net/nc/helper 操作及允许的放置，不直接声明 inst/subdesign。通过普通数组或带构造效果的 helper 创建的真实元件仍进入共享检查。循环指令和虚假容器元件不会进入制造 IR。同一个求值器与展开机制服务这些场景及其组合。

### 2. 一套表达式模型，两个值域

新求值器处理 **Int**（有符号的精确 64 位结构性整数）和已有 **Length** 类型。Int 不是第十二种电气单位，也不是缺少后缀的隐式物理量。可表示范围为 −2^63…2^63−1；字面量及每个中间值都检查。零和负的中间整数合法；各消费操作施加自己的值域限制。

| 运算 | 结果与规则 |
| --- | --- |
| Int `+ - *` Int；一元 `+ -` Int | Int，检查溢出；不回绕、不饱和 |
| Int `/` Int | Int，商向零截断；除数为零或 MIN/−1 报错 |
| Int `%` Int | Int，余数满足 a = (a / b) * b + r；除数为零或 MIN/−1 报错 |
| Length `+ -` Length；一元 `+ -` Length | Length，采用已有精确定点表示 |
| Int `*` Length 或 Length `*` Int | Length，检查精确缩放；Int 不转换为 Length |
| Length `/` Int | 仅结果可精确表示时得到 Length；除零、溢出或精度损失均报错 |
| Int `+` Length、Length `/` Length、Length `*` Length、其他单位算术 | 本 RFC 拒绝 |

因此 `10mm + n * 4mm` 合法，`10mm + n`、`3.3V + 1V` 和 `1mm / 0` 不合法。`1mm / 3` 若无法精确表示则拒绝，不进行舍入。求值后仍执行已有物理坐标范围检查，不依赖平台 libm。

Length 使用已有的 **以 10^-15 mm 为单位的有符号 i128 计数**（`UnitValue.femto`）；表达式中间值在该表示下检查。更窄的几何消费端边界，在已有消费阶段检查，不施加于全部常量/泛型值。算术产生的 Length 值按已有 `geom::mm_femto` 约定生成规范文本：最短十进制后接 `mm`，没有多余尾零或负零。因此 `1.00mm + 0mm` 产生值文本 `1mm`。字面量、包围字面量的括号、纯参数/常量转发保留原值文本；算术（包括 `-PITCH` 这样的值的一元算术）生成规范结果文本。紧邻已有带符号单位字面量的前缀减号，由 parser 合入该字面量（§10）：`-1.00mm` 保留原写法。这保证的是字面量/AST 语义，不要求 lexer 继续产生单个带符号 token。源码格式化另行保留表达式 AST。任何 emitter 都不能自创文本格式，或把未求值表达式放进 `UnitValue.text`。

整数字面量使用十进制整数，不引入新进制或小数写法。直接作用于十进制字面量的前缀符号，要先与其绝对值结合，再做 Int 范围检查，因此 `-9223372036854775808` 是有效字面量/默认值，`9223372036854775808` 则无效。其他一元操作正常求值并检查溢出：如果 MIN 已经是 Int 值，`-MIN` 失败。用括号包围带符号字面量会保留该字面量；包围越界的正数绝对值不会使其合法。必须明确测试 MIN、MAX、两侧紧邻的越界值、对 MIN 取负、MIN/−1 和负默认值。

运算符优先级从高到低为：基本表达式/括号 → 一元运算 → `* / %` → `+ -` → 区间分隔符。二元算术左结合。比较、布尔值、强制转换和幂运算不在语法内。按源码树顺序求值，不能通过重新结合掩盖溢出。

### 3. 局部常量与共享整数参数

允许在 design、fn、subdesign、电路循环和 layout 体内声明局部 `const NAME: Int|Length = EXPR`。const 不可变，不创建物理对象，也不是可导出声明。它可以使用可见常量、Length 参数、const Int 参数、外层绑定变量和可见数组的 `.len`。它不能读取引脚电压、实例 spec、registry 状态、文件或生成的放置结果。

`const N: Int` 同时扩展 **fn 和 subdesign** 的 RFC-007 泛型列表。调用保留 `helper::<N>(...)`；subdesign 使用点保留 `subdesign bank: Bank<N>` 和 `[Bank<N>; M]`。实参绑定、默认值、嵌套转发、解析与包可见性使用同一共享机制。Int 默认值仍须为显式整数字面量；Int 与 Length 实参允许规定的表达式。其他物理单位保留仅字面量/参数的规则。不增加数组值或 Int 值的运行时 fn 实参。

上下文中的 const 标记区分结构性值与已有的名为 Int 的 trait：若这样的 trait 存在，`N: Int` 保留 trait 约束含义。device 声明上的整数泛型仍被排除，并报针对声明所属者的 E406；物理引脚接口生成属于其已有的独立模型。device 的单位/trait 参数保持不变。Int 不是电气 spec 值。

同一词法体内的常量和数组长度构成无环依赖图，包括 subdesign 数组长度。允许同体内向前引用。对 `const N: Int = channels.len` 与 `subdesign channels: [RcChannel<1kohm, 100nF>; N]` 报告完整环。不能通过实例化 channels 来发现其声明长度。子作用域常量不逃逸到父级或兄弟作用域；layout 常量只在该 layout 及其后代中可见。

新常量、循环标签和绑定变量不能与可见实例、subdesign 使用点名称、数组、网络、端口、fn 形参、泛型参数、常量或外层标签/绑定变量冲突，也不能遮蔽它们。在定义检查时拒绝这些冲突。已有的同名网络续接仍合法。标签属于包含它的词法电路体；该体的 layout 块对于标签唯一性是透明的。绑定变量属于自己的循环体。互不嵌套的兄弟循环都可以绑定 i。

### 4. 一个数组求值器，保留已有引用种类

物理数组和 subdesign 数组的长度都接受 Int 表达式，并保持严格为正；零/负长度仍报 E211。`.len` 返回一个可见物理数组或 subdesign 数组名称的声明长度，不构造元素。标量没有 `.len`。这只是一个查询，不是通用成员自省：不能写 `bank.channels.len`，也不能跨端口边界读取私有 const。在 bank 自己的定义内部，可以正常查询其 channels 数组。

所有本来合法的单索引位置都使用同一个求值器，包括物理引脚、subdesign 端口、合法 fn 实参、数组形式的 subdesign 使用点，以及**已有放置路径中的每一个索引段**，如 `place banks[b].channels[i + 1].c at (...)`。每段的具体边界按该节点自身数组检查。这扩展的是选择器，不是访问权限：电气路径不能穿过私有内部结构访问 c，整个 subdesign 不能成为 Instance 实参，端口不能标为 nc。

区间/列表 fan-out 仍只用于 net 成员列表中的物理引脚和 subdesign 端口。比较基线保留包含末端的 `..=` 及已有可选步长形式；边界、列表项、步长接受 Int 表达式，要求步长为正、start ≤ end 且所有选中元素都在范围内。绝不裁剪越界元素。选择多个引脚或端口，为一条源码 net 贡献多个成员；循环迭代则可以贡献多条独立网络。

必须保留源码端点与选中下标的区别：长度为 3 时，`arr[0..=3 step 2].PIN` 只选择 0 和 2，因此有效；`arr[0..=3].PIN` 会选择 3，因此报 E202。新求值器不能在现有契约之上增加仅针对未选中端点的拒绝规则。包含末端区间的相等端点选择一个元素；基线也允许只有一个物理成员的 net。这些行为已用当前语法的合成探针检查，记录于 `docs/reviews/evidence/2026-09-12-m2-range-baseline.json`；不代表执行了 M2。

### 5. 有限 for 与允许的操作

本轮 A 修订用下列**提议的具名写法**明确语义。延后的比较与决策工作放在附录 A；设计 §7 说明该写法下的身份行为。

```text
for_stmt       := 'for' LABEL ':' IDENT 'in' expr '..' expr '{' loop_stmt* '}'
const_stmt     := 'const' IDENT ':' ('Int' | 'Length') '=' expr
int_parameter  := 'const' IDENT ':' 'Int' ('=' integer_literal)?
primary        := literal | IDENT | IDENT '.' 'len' | '(' expr ')'
```

半开区间 a..b 按顺序进入 a 至 b−1；端点相等时为空，端点逆序时报 E1404。进入前边界必须是具体 Int。允许带符号边界，以及依赖外层绑定变量的嵌套循环；负数组索引仍失败。不增加包含末端的 for、for 步长、可变状态、break/continue 或任意迭代器。

| 上下文 | A 允许的操作 |
| --- | --- |
| design/subdesign 内的电路循环 | const、net、nc、fn 调用、嵌套 for、放置子集 layout |
| fn 内的电路循环 | 相同操作，遵守继承的 fn 放置限制 |
| layout 内的循环 | const、place、嵌套 for；不允许 inst、subdesign、fn 调用、net 或 nc |
| 循环外的普通电路体 | 已有 inst/subdesign/fn 操作，加上 M2 const/for/数量表达式；保留既有所属上下文限制 |

在 A 循环中调用 fn，可以创建该 fn 的普通局部元件。A 限制循环体内的直接声明，不会把 fn 改为纯函数。Fn 已有的合法约束/属性仍可用，所有结果效果都计入预算。M2 不增加循环内的顶层声明/导入。

循环体内直接声明标量/数组 inst 和 subdesign 必须拒绝，空循环也不例外；若没有更具体的既有所属上下文错误，使用 E1406。在 fn 中使用 subdesign 仍报 E1307。先验证局部常量，再处理操作；验证跳过的循环时不分配假想实例。Fn 调用保留其普通局部声明及展开规则。嵌套循环维度不增加 `a[i][j]` 写法。

循环既不声明电气接口，也不声明坐标系。电路循环内的 layout 块限于 const/place/嵌套 for；普通 layout 块保留既有约束形式。可放置对象来自可见的普通声明及其既有合法 subdesign 路径。不引入循环外的 `loop_label[i].r` 接口。

### 6. 放置保留所属关系与覆盖语义

```cohdl
layout {
    for grid: n in 0..leds.len {
        place leds[n] at (10mm + (n % 5) * 4mm,
                         10mm + (n / 5) * 4mm)
    }
}
```

`at` 接受 Length 表达式；rotate 接受 Int，并按当前 0…359 规则检查；side 仍为字面量 top/bottom。继续共享已有定点变换。不引入间距、碰撞、布线或热求解器、新角度类型或焊盘/封装表达式语言。

放置上下文继承自 design/subdesign/fn 所属者，不从生成路径字符串反推。在 design 中，计算坐标使用板坐标系。在 subdesign 中，它们是该 subdesign 局部坐标系中的默认值，通过普通的外层锚点、旋转和板面组合。未锚定的 subdesign 保留现有的“不产生默认板级放置”行为。循环不创建额外变换或覆盖优先级。Fn→for→layout→place 仍报 E1007；fn 内的板框仍报 E1006。

A 可以放置已声明的 subdesign 数组，或通过 RFC-032 既有点路径覆盖内部实例。外层实例覆盖优先于该实例化继承的默认值。两条同优先级的源码放置若解析到同一目标，仍是重复（E1007），即使其中一条来自循环。迭代顺序不能引入后写覆盖前写。RC 例子只放置一次通道组，再覆盖一个继承的电容默认值；没有在板级优先级放置该电容两次。

A 不为新增直接循环局部声明扩展放置作用域。通过普通引用重复放置已有具名对象，或放置具名 subdesign 并覆盖可访问的子对象。Fn 局部元件仍不能通过内部路径放置；循环标签不是公开分组地址。

### 7. 共享层级机制与循环身份

名称写法与对象种类不同。当前数组通过 `element_name(base, i)` 派生元素名；subdesign 和 fn 展开扩展 `Scope.path`，物理子对象路径进入同一个位号分配器。M2 必须扩展共享的路径构造/来源机制，不能建立独立分配器，也不能从字符串前缀推断物理类型。

| 身份来源 | 已有或候选路径 | 可寻址性 |
| --- | --- | --- |
| 已有物理数组元素 | `Board::leds_3` | 现有物理实例/引脚上下文 |
| 已有 subdesign 数组子对象 | `Board::channels_3::c` | 电气访问走端口，放置走现有点路径 |
| A 循环生成的操作/helper 局部对象 | `Board::__for_wiring_3::LINK`、`Board::__for_decouple_3::__fn0_helper::c` | 操作来源；fn 局部对象不获得放置访问能力 |

提议的 `__for_LABEL_VALUE` 路径段是内部词法帧，不是另一个 subdesign 节点。它没有端口、part、位号、BOM 行、默认布局或隐式覆盖优先级。其包含的真实子对象使用普通机制。复用帧实现，不能成为发明公开循环对象的理由。反过来，今后若让循环拥有公开组访问，也必须明确决定接口与兼容性。

只对预先声明的对象接线或放置的循环，**绝不改变该对象的父级归属**。扩展 RC 数组保留原有 `channels_0`…`channels_9` 子对象路径。即使在 A 中，循环生成的网络和 fn 调用也需要独立来源。对具名基线，以循环标签和实际整数值作为帧键，不使用源码顺序号或行号。非负值使用十进制文本，负值使用 neg 后接绝对值。通过现有保留名规则保留 __for_ 名称族，并针对嵌套数组/subdesign/fn 路径测试单射性。

每次迭代拥有自己的 fn 调用和匿名网络计数器，不消耗父级旧有计数器。迭代内的 net 声明使用其词法作用域：不同迭代中的同名局部网不会短接；同一帧内普通的同名网络续接仍保留。显式共享引脚/端口通过现有规则并网。私有网不凭打印名称逃逸。

重排不同标签的循环或扩展区间，会保留存续的标签/值路径。重命名标签则有意改变生成路径。帧**内部** fn 调用已有的顺序身份限制仍然存在：重排这些调用可能改变其对应用途，而锁差异并不能提供有效提示，因此还要比较连接/物料/布局。重复标签报 E201；重复硬编码的位号覆盖仍按普通规则失败。

### 8. 静态检查、具体绑定与最终组装

对于所有已提供的 fn/subdesign 定义和新循环作用域，可静态判定的声明错误必须一致地被拒绝，不取决于调用、M2 语法或从选定设计的可达性。带类型环境决定哪些事实已知：符号/种类解析、名称重复/遮蔽、泛型实参数量/默认值种类、单位兼容性及已有依据的 trait/引用约束。依赖未知具体器件或值的约束等待替换；调用者未使用的 const 不能改变被调用者的检查义务。附录 B 记录后续验证器工作及其兼容性影响。

同一个带类型求值器在三个环境中使用：

1. **定义验证：** 已知参数及循环变量的类型，具体值可以未知。解析符号义务并求值具体子表达式。C: Capacitance 时，即使未调用，`SeriesR<C>` 也无需 C 值就会失败。空循环不能掩盖已知的声明/签名/表达式错误；A 按上下文拒绝禁止的直接 inst/subdesign 声明。
2. **实际 fn 或 subdesign 激活：** 绑定实参/默认值，再在该替换下验证完整体，之后才物化子对象。依赖这些实参的值变为具体值，包括空嵌套循环内部的值。已声明的 subdesign 数组正常激活每个实际元素。
3. **实际迭代：** 绑定该整数，验证新变为具体值的表达式，并贡献 A 允许的操作。嵌套调用/循环重复这个过程；普通 subdesign 激活贡献其自身允许的体。仅类型验证不分配假想对象或动态循环帧。

即使被除数未知，已知除数为零也会失败：空循环内的 i/0 失败。1/i 等待实际 i。不能通过代数化简为未知量编造值。常量按确定性的依赖顺序求值，在各自带类型/已绑定环境内记忆化，不能跨不兼容绑定复用。

当 f 含 `for empty: i in 0..0 { const BAD: Int = 1 / N }` 时，调用 `f::<0>()` 在实际绑定下失败。`for none: i in 0..0 { f::<0>(); }` 不发生实际 f 激活：检查其签名和实参表达式，但不对被调者做值特化。其中的 `f::<1 / 0>()` 仍在实参表达式处失败。循环体内直接使用 subdesign 必须拒绝，空循环也不例外。成功的空循环不贡献元件、逻辑节点、端口、网络或放置。

展开后执行已有并网、required 端口验证、物理引脚义务和残余 DRC；build 保留物料/封装/位号义务。helper 可以将调用者拥有引脚的后续连接留给调用者；临时端口成员必须保留到 required 端口检查和并网完成。循环展开不能抹除 required 端口，也不能将其当作物理 nc。错误经过后续检查时，仍保留原始源码、实际绑定和 fn/subdesign/迭代来源。

### 9. 覆盖完整展开图的确定性工作量限制

预算启用与生成工作计数独立于声明类型检查。先遍历**以所选 design 为根的完整语法展开引用图**。跟随每个 fn 调用和合法 subdesign 使用点类型，包括嵌套 subdesign 数组、subdesign 调用的 helper，以及词法上位于循环内的 fn 调用。使用已访问集合检查每个到达定义的签名/默认值及体。Device/part 引用不贡献可执行体；仅在包中声明无关函数/subdesign 不使其可达。循环次数和 const 是否使用都不裁剪此遍历；遍历不实例化定义。

若此图含有允许的 M2 const、const Int 参数、循环、`.len` 或算术表达式，则启用计量。仅有旧的字面量数组语法和普通单位参数转发，不启用计量。因此，到达的 subdesign 中的 Int 默认值会启用计量；可达但实际跳过、内部含 M2 的 helper 也会启用；无关、未调用的 M2 定义不会启用。已访问集合不允许递归：已有 fn 和 subdesign 环规则仍在各自规定阶段独立执行。

**必须有具体回归：** 选定 design → subdesign 包装层 → 体内使用 M2 的 helper，而选定 design 自身没有直接 fn 调用或 M2 语法。在第一个生成对象之前就必须启用计量。还要测试没有 fn、仅最深层体含 M2 的嵌套 subdesign。此前仅遍历 fn 的发现规则已移除，不能留作未来集成问题。

完全使用旧语法的选定图保留旧的资源限制行为。这个兼容性例外不承诺限制每一块旧的大型 subdesign 板。一旦启用计量，就覆盖**整个实际展开**，包括更早的旧语法声明，以及全部 fn/subdesign 激活的后代。源码重排、死常量消除和优化器缓存不能改变启用结果或计数。

限制为：累计实际进入的循环迭代 100,000 次、生成工作项 1,000,000 个、同时活动的循环帧 64 个（包括跨 fn/subdesign 激活的帧）。逻辑节点本身不是循环帧。这些是提议的语言常量，不是基于主机内存的启发式限制或墙钟超时；超过限制必须在追加/物化超额项之前确定性地硬失败。

| 实际语义事件 | 物化前计入的工作项 |
| --- | --- |
| 物理标量/数组元素 | 每个真实实例 1 项 |
| fn 调用 | 每次进入的调用 1 项，再加它贡献的全部项 |
| subdesign 标量/数组元素 | 每个逻辑节点 1 项，再加它声明的端口和贡献的项 |
| 已实例化的 subdesign 端口 | 每个端口 1 项，包括 optional/未连接端口；这是逻辑工作，不是 BOM 元件 |
| 源码端口连接块条目 | 每条 1 项，再为其标量目标引用计 1 项；合成连接不额外计为源码 net |
| 源码 net/nc/place 语句 | 每条展开语句 1 项；net/nc 还在去重前为每个展开成员计 1 项 |
| 布局约束 | 每条展开声明 1 项，再为每个源码 net 引用计 1 项 |
| 物理属性 / 差分对物理参数括号 | 每条解析后的记录 1 项，再为每个源码 pin/instance 目标计 1 项；差分对括号在约束本身之外另计 |

仍禁止给整个 subdesign 数组附加一份端口连接块。允许的标量连接块中，目标是标量 pin/port/net 引用；fan-out 仍只用于 net 成员。内部 required 端口检查和并查集步骤，不增加依赖优化器实现的计费。按规定计引用，不是为走过的每个路径段都计费。派生几何/输出行不会悄然成为新的工作事件。

数组基名、const 声明、layout 块和循环头不单独增加工作项。逻辑节点即使为空也**要**计数，因此空嵌套 subdesign 不能放大未计量展开。即使内部没有真实元件，端口声明也**要**计数。重复的源码成员在合并前计数。通过普通声明、数组、helper 或 subdesign 到达的物理后代都计费。空循环不贡献生成工作。

保留普通的“先声明、后操作”遍历：递归按声明源码顺序及实际进入的整数顺序处理，再按顺序计入源码操作及其成员/引用列表。延后的放置/端口操作必须在分配记录之前计费。用检查过的算术计算大数量，并在批量克隆/分配前拒绝超预算请求，同时保持与逐项计费相同的第一个失败源码位置。不能仅为计数就分配一百万个假设对象。优化不能改变第一个失败事件、判定或报告的计数/限制。

计数示例：两个预先声明的单引脚真实实例计 2 项；一个两次迭代的循环每次生成一条单成员 nc，计 4 项；另一个两次迭代的放置循环计 2 项。合计 8 个工作项、4 次进入迭代；两个循环内部都不声明 inst。含一个未使用 M2 const 及 `subdesign nodes: [Empty; 2]` 的板，即使 Empty 没有端口或物理子对象，也计 2 项。单端口标量 subdesign 内含一个电阻及一条源码双成员网，在调用方贡献之前计 1 节点＋1 端口＋1 实例＋1 网＋2 成员 = 6 项；最终连接义务仍适用。资源工作与制造元件不同。

引用遍历只负责选择是否计量；§8 统一检查声明，不再使用第二套特性传播策略。两个过程都不对未进入的激活进行值特化。这些限制约束的是规定的展开事件，不约束源码解析、全部旧资源使用或后续几何输出。常量依赖环被拒绝；记忆化避免常量重复求值出现指数放大。展开失败不输出新的成功或截断构建结果，并保留已有产物失败/所有权策略。

### 10. 诊断与词法兼容性

当含义适用时复用已有错误：E201 名称冲突、E202 已解析索引越界、E211 无效数组形状/长度、E401 泛型实参数量、E403 trait 约束、E110/E111 物理单位不匹配/缺失单位、E112/E113 单位泛型实参，以及已有布局/DRC 错误。新泛型标记用于不支持的声明所属者时使用 E406。E201 注册表表述必须从“重复顶层声明”扩展为覆盖已有词法作用域冲突和新循环名称；`expand.rs` 已对这些情况发出 E201。这是明确的文档对齐，不是未经分配的新错误含义。运算符值域错误使用 E1401；消费字段上的物理单位不匹配使用已有 E110/E111 或泛型 E112/E113。要求 Int 却得到 Length 表达式时使用 E1401。新支持的负 Int 表达式可以进入 E202/E211 边界检查，不再停在旧词法 E102；应记录这一有意细化的诊断，同时对仍不接受 Int 的负裸数消费位置保留 E102。

提议新增错误块，接受时由中央注册表统一分配：

| 候选错误码 | 失败种类 |
| --- | --- |
| E1401 | 期望编译期 Int/Length 或受支持的操作数组合；遇到非整数数值、错误种类或不支持的属性 |
| E1402 | Int/Length 表达式溢出或无法精确表示的 Length 除法 |
| E1403 | 除法/取余的除数为零 |
| E1404 | for 区间逆序 |
| E1405 | 超过确定性展开预算/深度 |
| E1406 | 当前循环或表达式上下文不允许该声明/操作 |
| E1407 | 常量/数组长度依赖成环，指出完整环 |

主 span 指向失败的最小原始构造。对于依赖展开的错误，**主消息**必须携带违反的约束、失败的具体值/合法边界，以及包含相关绑定、简短且可区分的激活路径，例如 `Board::bank::__for_links_9, N = 10, n = 9`。即使消费者只显示 code/message/primary span，关键信息也必须保留。次级标签增加外层 fn 调用/subdesign 使用点、循环头及确立边界的声明 span。保留 RFC-010 schema_version 1 和现有 message/secondary/help 字段。展开错误的内部去重键必须包含展开帧，不能仅因为源码 span 相同就悄然混同两次失败迭代。不引入隐藏的诊断截断。

求值器的 Int 值域不能削弱 Voltage 或 Length 位置对裸数的拒绝。`rotate` 仍是独立的既有整数值消费位置，不是物理单位强制转换。

词法处理需要有意识地检查兼容性：`for` 已是 `impl Trait for Device` 使用的 token；`const` 和 `in` 只在新语法位置中作为上下文关键字，不全局保留这些标识符。不能把普通的缺失运算符变成隐式乘法。

**减号只有一种词法形式。** 在字符串/注释之外，每个 `-` 都是独立标点 token，即使后面紧跟数字；随后数值 token 本身不带符号。移除当前 lexer 中吸收后续数字、以 E102 拒绝负裸数，或声称 `-` 只能作为 Temperature/Length 符号并拒绝其他用法的分支。数值写法、后缀和源码 span 仍交给共享字面量读取逻辑；即使校验移出扫描器，带符号单位校验也必须保留现有规则与诊断。内部 token 形状不属于源码/IR 兼容性承诺。

**parser 在允许的语法内确定减号角色。** 表达式期待操作数时，`-` 是前缀；已完成左操作数后，它是二元减法，遵循 §2 的优先级。因此 `n-1` 与 `n - 1` 得到相同表达式树；`-PITCH` 是前缀算术，`n--1` 是减去负数字面量。循环头解析先消费上下文关键字 `in`，再开始下界表达式，所以 `in -1..N` 从前缀符号开始。不能全局按前一个 token 的种类分类减号：`in` 在循环头之外也可以是普通标识符。旧的仅接受字面量的字段不因此获得表达式语法。

**字面量组装保留带符号单位兼容性。** 当语法期待字面量或前缀操作数时，紧邻数值单位写法的减号构成既有带符号字面量，包含原始完整文本和涵盖符号的 span。所有消费位置共用相同字面量校验：`-1.00mm`、`-40C` 保留值/文本，`-5V` 仍报 E105。二元减法的不带符号操作数不是负数字面量：`1mm-1mm` 是两个正 Length 字面量相减。前缀减号与单位写法之间有空格、注释或括号，就不组装为字面量。在允许的 Length 表达式中，`- 1.00mm` 和 `-(1.00mm)` 是一元算术，生成规范值 `-1mm`；既有写法 `-1.00mm` 则保持字面量文本。Fmt 必须在重新解析后保留这个 AST 区别及字面量写法。这不增加 Temperature 算术：`- 40C`、`-(40C)` 仍不合法。单位后缀、精度、范围和无符号单位负值检查均不放宽。

对于十进制整数，§2 的直接符号范围规则适用于 Int 语法，包括仅接受字面量的 Int 默认值；空格或注释不会增加中间表达式节点，括号则会。旧的负裸数消费位置保留 E102；允许的 Int 表达式改用规定的表达式/边界诊断。不能仅因移除了 lexer 报错，就让负裸数电气值合法。回归测试必须覆盖旧的泛型默认值/实参、spec、坐标及其他字面量消费位置，不能只测新增 const 表达式。

保留当前的最长单位后缀规则：**`10%` 是 Tolerance 字面量；`10 % 3` 使用取余**。拒绝 `10%3`，不能根据预期类型重新解释单位字面量；fmt 总是在二元运算符两侧加空格。测试以上全部符号案例、Int MIN/默认值、二元减法后接一元符号、`0..10`、`0..=9`、`//` 注释，以及针对性的 E101/E102/E105/E106 诊断。增加 parse → fmt → reparse 检查，覆盖 Length 字面量与一元算术的文本区别及涵盖符号的 span。不允许依赖符号表的分词或无界前瞻。

## 类型系统优先检验

本 RFC 不增加规则/DRC 检查。单位替换、trait 以及 Pin-vs-Instance 要求仍是类型层面的义务。Int 范围/索引/溢出检查和有限生成限制，是编译期展开义务。required 物理引脚与 required subdesign 端口是结构义务，在各自已有的最终组装阶段检查，因为只有这时调用者连接才确定。已有涌现的电气检查仍属于残余 DRC。

保持性标准很具体：每个生成实例携带的已解析器件、spec、引脚角色/义务、trait 绑定和最终 part 要求，必须与等价的手写实例一致。泛型或重复构造不能把失败检查替换为未检查占位对象，不能抹除 required 引脚，也不能将缺失数据当作成功。编辑器可以在已有错误状态下保留部分模型，但这不是成功构建。

必须有三个配对失败探针：RC 参数单位错误（也包括嵌套转发）、索引类型为 Int 但越界的 LED 引用，以及实际生成通道上的 required 连接缺失。再加第四个探针，故意交叉连接仍类型正确的通道：拓扑判定器必须捕获不匹配，同时不能谎称语言能够推断意图。这样让例子对应判定阶梯，而不只是统计生成对象。

## 概念影响与明确修订

永久新增能力是**通过有界编译期求值进行带类型的参数化电路构造**。概念成本是纯值/效果的区别和避免名称捕获的迭代帧。A 保持在普通电路体和数组中声明，并重复调用带构造效果的 helper。直接局部声明及其受限外部寻址能力随 B 延后。For、数组选择器和 const 泛型实参使用同一机制；不创建独立的“数组算术”“布局算术”或“模块编程”引擎。

评审指南的 P01–P10 是已有原则的可追溯标签，不是新的规范权威：

| 原则 | 在本 RFC 中的具体结果 |
| --- | --- |
| P01/P02：可检查的承诺、最早信息充分处 | 定义/带类型绑定检查、具体索引验证，然后是最终引脚义务；必须有配对反例 |
| P03/P05：共享语义、显式来源 | 复用 inst/subdesign/fn/net 和泛型绑定；显式共享引脚会并网，同名局部写法不会 |
| P04/P06：固定输入、持久身份 | 纯求值、精确锁定依赖、具名迭代路径；重复构建字节与编辑稳定性分别测试 |
| P07/P08：物理责任、工具 | 每个生成 part 仍留在流水线中；格式、诊断、LSP 和符号化文档随特性一起交付 |
| P09/P10：有边界的承诺、显式演进 | 披露意图/模拟/物理缺口及后延能力；仅通过接受流程修订受影响的 Accepted 契约 |

| 现有契约 | 所需明确修订 / 保留边界 |
| --- | --- |
| RFC-001 单位 | Int 不属于物理单位集合；精确 Length 运算复用其表示和零强制转换规则。E102 必须明确停止拒绝新允许整数上下文中的负 Int 字面量 |
| RFC-007 泛型 | 同时修订排除非单位 const 泛型的规定，以及 Length 实参仅允许字面量/参数的限制。通过共享替换为 fn/subdesign 增加 `const N: Int` 和 Length 实参表达式；默认值仍仅限字面量 |
| RFC-024 数组 | 将仅字面量数量/索引替换为检查过的 Int 表达式；保留正长度、真实元素和仅 net 内 fan-out |
| RFC-032 subdesign | 保留带类型端口、层级与布局契约；明确扩展数量/索引计算、局部 const/for、共享声明验证和完整展开图计量 |
| RFC-006 fn | 保留带构造效果的调用和真实局部对象；共享参数绑定/来源信息；保留实际调用环规则；明确加强静态可判定的声明验证 |
| RFC-005 身份 | 已有数组路径和分配器不变；规定循环生成路径，并披露编辑引起的身份变化 |
| RFC-009/010/011/014 工具 | 规范格式、span/来源信息、已注册错误和 LSP 理解必须一起交付 |
| 包 API 文档契约（`docs/apidocs.md`） | 显式为符号化体/签名表示做版本管理，见工具部分。诊断 JSON 保持版本 1 |
| RFC-013/020/025/026 布局 | 用既有几何规则求值位置/旋转，继承 design/subdesign 放置上下文。仍排除 fn 局部内部访问、直接循环局部放置作用域和 pad 表达式；不增加布线或电气推断 |
| RFC-029/030 依赖 | 离线 check/build 和精确锁定包不变；表达式不能查询 registry/网络状态 |

这些仍属于 cohdl.dev 的语言/编译器职责。cohdl.ai 可以生成源码并消费判定，但不能提供第二个预处理器、私下解释循环，或选择不同算术/限制。Konnect/KiCad 操作编译器输出，并执行它们正常的物理检查。

## 一致性矩阵条目

| 概念 | 语法 | 判定器 | 诊断 | 网表 | 兼容性 | 信任 |
| --- | --- | --- | --- | --- | --- | --- |
| 高 | 高 | 高 | 高 | 高 | 高 | 高 |

- **概念：** 用依赖数量的真实数组与有限迭代论证 Int/const。排除运行时值及物理 spec 算术。保持 module、subdesign、fn、Instance 和 Net 的含义不同；延后 B 的额外声明作用域。
- **语法：** 一个优先级表和表达式 AST；const 泛型扩展现有列表。比较基线只用一种循环区间形式；明确审查保留包含末端 fan-out 所带来的端点写法成本。上下文写法避免抢占已有声明名称。
- **判定器：** 静态体验证加每个使用点的具体展开，之后执行现有流水线；没有忽略语句、隐藏未知值或跳过真实 part。
- **诊断：** 原始 span 和展开帧经过已有 check/build JSON 与 LSP 保留；必须测试负数/空循环/溢出。
- **网表：** 循环局部名称不能短接兄弟迭代；没有虚假循环元件。与手工展开设计比较图等价性，包括全部引脚、NC 和放置。
- **兼容性：** 除已声明的统一验证修正会拒绝过去漏检的无效定义外，RFC 之前有效源码的黄金输出和 design.lock 必须字节一致；带符号/单位词法及旧 fn 计数器需要专项回归。将源码重构为具名循环是设计编辑，可能改变作用域网络/fn 局部名称；不能错误承诺该改写前后的字节相同。
- **信任：** 边界/资源违规时确定性失败，没有依赖时间的求值或部分成功；展示安全重复和可见失败两方面。

这不是低影响的解析便利功能。接受时必须在同一设计变更中更新受影响规范章节和决策记录。实现不能一边依赖被取代的限制，一边声称 RFC-007/024 未变。

## 可检验性与退出条件

## AI 可生成性

先教既有对象模型：物理数组命名元件，subdesign 数组命名可复用的带端口区域，fn 展开带类型片段，循环重复允许的操作。同一个求值器计算数量、选择器和坐标。诊断在原始源码 span 报告实际绑定/索引/上下文。A 的私有构造可能需要提取 helper/subdesign；明确披露该成本，而不是用循环内直接声明的捷径隐藏它。

修复任务很具体：最后一个索引失败后，把相邻连接循环从 `0..leds.len` 缩短为 `0..(leds.len - 1)`。范围内却接到错误通道的连接仍可能类型正确，所以独立拓扑检查仍必要。RC 布局任务检验后续代理能否准确找到并调整一个元件，而无须重建其构造抽象。

## 已选范围与延后方案

1. **候选 A——本轮 M2 已选。** 可计算的数量/索引、fn/subdesign 共享的 Int 参数/常量、net/nc/调用的操作循环及针对具名对象的放置循环。声明仍位于普通 design/subdesign/fn 体中，遵守既有所属上下文规则。三个指定工作流无需新的私有构造声明作用域即可表达。临时性重复构造可能需要提取 helper/subdesign。
2. **候选 B——延后，不是 M2 的可选开关。** 会在允许的循环体内增加直接 inst/subdesign 声明，包括按迭代特化。私有局部对象需要声明作用域、身份及放置/访问契约；其直接局部 RC 写法本身不满足独立布局工作流。只有真实工作负载表明 A 的提取成本显著后，才重新考虑。延后不代表局部构造本身不健全。
3. **纯 fn 加仅由 subdesign 构造。** 这是独立的语言角色与迁移提案，不是选定 A 的结果。必须覆盖 Instance/trait 约束 helper、物理属性目标、嵌套生成元件及锁/源码兼容性。当前 fn 仍保持带构造效果。
4. **现在就引入宿主语言解释或通用计算。** 计算/控制流更广，但需要本次 M2 子集之外的效果、终止性、打包和诊断契约。tscircuit 提供的是编写体验证据，不是 CoHDL 正确性或身份保证的证明。其 map 例子把重复构造与可供其他声明引用的字符串名称结合起来。CoHDL 排除了源码标识符生成和循环局部引用逃逸，因此不能假设 B 的私有局部对象拥有同样的外部编辑机制。这使该例子无法独立论证 B 对后续外部放置任务的必要性，但不能反证局部构造在允许作用域内的用途。现有具名物理/subdesign 数组仍可供两个候选使用。

选择 A 的依据是相同任务下的拓扑、外部编辑、生成身份及概念/编译器/工具成本比较；既有语法 RC 基线提供了实际编辑证据。M2 本身仍未实现。未来若再提 B，必须指出 A 的具体限制，并在相同接口及检查下比较。仅语法更短或得到外部不可编辑的等价图，不足以构成证据。

语法策略比较和声明验证器实现是附录 A、B 中延后的后续工作。当前 RFC 评审仍明确保留拟议写法和设计 §8 的检查契约；调整后续工作的组织位置，不代表接受某种语法或削弱这些义务。

## 兼容性

这里明确修订已接受的排除项，而不假装所有旧文本仍有规范效力。不替换现有数组写法。未使用新构造的已有有效源码必须保留判定、design.lock 和每个输出字节，只有一项明确提议的修正：过去声明检查器漏掉的静态无效、未调用定义，现在按设计 §8 统一失败。应逐一明确新增拒绝案例，不能承诺无条件保留过去每一次成功检查。过去无效、现在允许作为整数表达式的语法遵守新诊断规定；这不是承诺继续拒绝新特性。引脚编号、带符号物理字面量、名为 Int 的 trait 参数、旧物理消费位置的负数错误及 `%` 容差字面量，都需要正常循环 fixture 之外的回归覆盖。

**对空白敏感的 `%` 是明确的词法取舍。** 现有 `10%` 保持 Tolerance 字面量；`10 % 3` 成为整数取余；`10%3` 被拒绝，不能用预期类型重新解释。这在保留旧单位 token 的同时增加了空白敏感的运算符边界。fmt 为二元运算符加空格，但不能消除编写成本。要测试分词、补全和往返格式化；接受时必须承认该取舍，或明确选择不同运算符写法。

**区间与诊断兼容性：** 比较基线中保留的包含末端 fan-out 与半开 for 并存。增加半开选择器属于 RFC-024 的增量修改，需要单独规定空区间规则。更新注册表时，`docs/error-codes.md` 必须反映 E201 已有的更广泛用法，并保留旧 E130x 对端口/容器的区分。

采用循环可能重命名匿名/局部网或 fn 局部路径。应保留拓扑与已有数组身份，检查锁差异并协调布局映射。不要自动迁移已布线板，也不要用 fmt 改写全部源码。纯常量算术不引入非确定性依赖输入。

## 工具与运维

以下是建议的实现接点，不是实施授权：一个表达式 AST/求值器；共享泛型替换环境增加 Int；选择器 AST 保留表达式直到具体解析；电路体/layout 遍历器保留 loop 和 const 节点，不做源码文本替换。经过词法迭代帧时携带已有 Design/Sub/Fn 放置所属者；不能用板坐标替换 subdesign 相对默认位置。在后续诊断使用的共享已检查数据中保留原 span 和展开来源。

`cohdl fmt` 只格式化，不展开或常量折叠作者源码。除幂等性外还要验证语义保持：删掉 `(n + 1) * 2` 的括号，可能产生不同但仍不越界的电路。LSP 识别常量、循环绑定变量和数组声明；当单次实例化可确定具体长度/值时显示它们。泛型/循环引用可能对应多个值，不能任取一个值当成普遍结果。没有 relatedInformation 的 LSP 客户端，以及 Explorer 现有仅消息式诊断投影，仍应收到第 10 节规定的关键展开上下文。Explorer 消费同一批展开实例及原始源码映射，不存在第二个 JS 展开器。

**包 API 文档需要明确的版本契约。** 基线 `body_summary` 输出平面的 insts/calls/nets 和数值数组长度（subdesign 使用点已在 inst 列表中携带种类标记）；它不能通过报告零条网或编造长度，真实描述一个尚未实例化的 N 元素循环。提议的最小要求是：

- 需要 M2 签名/体表示的文档采用包 API 文档 `schema_version: 2`；输出条目不需要新表示的文档仍用版本 1。这独立于诊断 JSON，后者保持版本 1。已有版本 1 字段含义不变。
- 在版本 2 中，Int 泛型在已有泛型描述符中使用 `bound: {"const": "Int"}`；`name` 与字面量文本 `default` 保留含义。单位/trait 描述符保留既有形式。
- 自身签名或词法体使用 M2 的每个 fn/subdesign/design 条目，都在以种类命名的 payload 中提供 `body_source` 字符串。它是带花括号的完整体，采用规范 CoHDL 格式，保留常量、符号长度、嵌套、标签和表达式。省略该条目旧有 insts/calls/nets 摘要字段，不能把不完整的直接语句数量当作总数。保留 subdesign 端口描述符及其义务；其他条目字段保留现有含义。使用同一个格式化器；不能另建体渲染器或暴露竞争性的可执行 JSON 语言。
- 现有泛型实参字符串列表中的 M2 值表达式，使用规范的作者表达式文本，不使用猜测值。派生的具体 spec 值使用第 2 节的值文本规则。如果输出的本地或 foreign 条目需要任何一种新形式，所属文档使用版本 2。
- 在声称支持版本 2 上传之前，registry 上传验证/存储和 viewer 必须同时支持两个版本。尤其要更新当前仅接受版本 1 的外层格式验证器。将 body_source 渲染为经过转义的源码文本，识别 fn/subdesign/design payload 中的 const Int；不求值循环、不显示编造的展开数量。不支持的版本必须明确返回格式不支持，不能自动降级为空摘要。

在已接受的实现中更新 `docs/apidocs.md` 及编译器→registry→viewer 契约测试。公开的版本 2 形式属于范围选择，不是“自动增量兼容”。sidecar 仍独立于包 tar/哈希身份；已有尽力而为的 docs 上传，不能把一次成功的包发布变成失败。准确签名/源码视图之外的 viewer 呈现可后续单独推进。

不要求新增 CLI 命令、插件、网络调用、JSON 诊断 schema 或制造方言。修改不能增加编译器依赖，也不能泄漏无序映射迭代。M2 不能在工具中丢弃已有 subdesign 路径或端口元数据。更丰富的导出层级仍是 RFC-032 的实现义务；本提案不悄然宣称它已完成，也不免除它。

## 教学成本

先从一颗、两颗 LED 开始，再学习带具名数组元素及独立布局的 RC subdesign。解释 Int 与单位、一网 fan-out 与重复网络、包含与不包含末端，以及类型信息与具体值。提议的循环标签命名操作站点，不是电路对象。将 helper/subdesign 提取作为 A 的构造路径教学；B 仅作为延后的设计历史提及。源码简短与永久概念成本是不同评审维度。

## 失败模式

验收表覆盖差一位错误、静默短接、真实元件消失、默认值作用域错误、隐藏的空体错误和资源耗尽。还要防止错误承诺：生成成功不是电气仿真；间距可计算不证明净距合格；数值 N 参数不负责转换器选型；E140x 错误块不替代已有物料/引脚/DRC 检查。

区分带错误的编辑器数据与成功构建。例如，tscircuit 的[重名检查阶段](https://github.com/tscircuit/core/blob/c298605b2779793876f20f1139a2ebd024a1d7f3/lib/components/base-components/NormalComponent/NormalComponent.ts#L236)记录错误，并把冲突元件标记为待移除；其他渲染路径可以抛出异常。CoHDL 可以保留明确显示失败状态的编辑器部分模型，但不能在为恢复错误而丢弃必需元件后报告构建成功。仅仅产出含错误记录的模型，既不证明成功完成制造交付，也不证明输出字节不确定；这里关键的区别是成功判定及其覆盖的对象。

## 附录 A：后续工作——语法比较与决策

**延后的后续材料。** 按用户当前要求，直接推进的任务是完成 RFC。本附录保留后续讨论所需的备选方案与建议，不选择新的语法策略，也不启动编译器实现。正文例子继续使用提议的具名循环及包含末端 fan-out 写法。

**2026-09-12 已准备语法建议：** `docs/proposals/decisions/m2-a-syntax-options.md` 在相同工作流下比较了三种标签策略和两种区间策略。它建议强制循环标签，并在半开 for 之外保留包含末端/列表 fan-out（L1 + R1），同时保留已说明的词法取舍。这些是可评审建议，尚非单独获批的语法决定。材料披露了纯放置循环额外标签的成本、可选标签的序号身份限制和实测选择器行为；声明审计仍未完成。

### A.1 循环标签

| 策略 | 收益 | 需要评估的成本 |
| --- | --- | --- |
| L1：每个循环都由作者提供标签 | 一种循环头形式，明确操作使用点身份 | 纯放置循环也需要名称，尽管被放置对象已经有身份 |
| L2：所有位置都允许省略标签 | 循环头简短；相同输入仍可具有确定性 | 插入/重排无标签使用点会改变自动词法序号；后来加标签会改变生成路径 |
| L3：只允许在 layout 内省略标签 | 放置循环简短，不需要推断被调用者的效果 | 循环头是否合法依赖上下文；移入电路体后必须补标签 |

**上述机制没有解决强制标签的成本问题。** 具名基线为每个循环命名，包括纯放置循环，以避免过早发明效果推断或匿名使用点匹配。可选标签方案必须解释具名/匿名网络、重复的带构造效果 helper 调用，以及后来增加构造语句的编辑如何确定身份；仅放置循环可能需要来源信息，却不需要持久对象身份。接受前要比较这些成本。这里不声称更短语法必然牺牲正确性，也不声称基线写法是唯一必需选择。

`docs/proposals/decisions/m2-a-syntax-options.md` 中的详细比较规定了可选策略的具名/自动身份编码、词法序号归属和 fmt 行为，并在 LED、RC 与嵌套复用任务中比较循环重排、范围扩展、标签修改及新增 helper 调用。helper 可以加入含有 layout 块的电路循环，不能直接插入 layout 循环。L1 会拒绝无标签兄弟循环，而非悄悄分配身份。任何策略都不能消除帧内 fn 调用已有的序号限制，标签也不会创建公开的 subdesign 接口。

### A.2 区间写法与词法取舍

**区间端点写法是明确的范围决策。** 半开循环与包含末端的 fan-out 并存，会形成两种约定，与它们的电气效果无关。保留已有 fan-out 可以最小化对 RFC-024 的修改。另一方案是在保留旧语法的同时增加半开 `arr[0..arr.len].PIN`。该方案还需要规定空选择/成员数量、步长语义、诊断和 fmt 测试；本提案没有隐含纳入它。应在接受时做出决定，不能声称“一条网”的语义解释了写法差异。

| 策略 | 用于比较的具体契约 | 剩余成本 |
| --- | --- | --- |
| R1：半开 for 之外保留包含末端/列表 fan-out | 包含末端的相等端点选择一个元素；循环相等端点不进入迭代；检查实际选中下标 | 保留两种端点约定 |
| R2：额外允许半开 fan-out | 保留旧语法；选择 a + k × step < b；要求正步长且 a < b，否则 E211；检查选中下标 | 增加一种选择器形式及保留分隔符的 fmt/诊断；若允许空选择，还需进一步决定 |

两种策略都不为 net 增加两个成员的最低要求，也不把步进时跳过的端点当作数组访问。已有 15 项数组测试和十个合成选择器探针记录在 `docs/reviews/evidence/2026-09-12-m2-range-baseline.json`。21 个输入的旧 lexer 记录是 `docs/reviews/evidence/2026-09-11-m2-lexer-baseline.json`。它们建立当前行为基线，不表示未来 M2 实现已通过。设计 §10 和兼容性章节保留了带符号字面量/减号，以及容差后缀/取余的明确词法取舍。

### A.3 后续再推进的事项

1. 用正文三个场景评审标签和区间的成本，再记录所选语法及词法取舍。
2. 若选择发生变化，同步两版 RFC 的语法、示例、身份保证、诊断和 fmt 要求。
3. 分开记录源码模型比较、基线测试和实际 M2 执行证据。在记录决策之前，L1 + R1 仍是建议。

## 附录 B：后续工作——声明验证器与兼容性审计

**延后的实现与验证工作。** 当前任务是 RFC 编写和评审，不是构建该原型或运行其新旧比较。设计 §8 保留语言层面的义务：一致地拒绝静态已知错误，推迟依赖未知具体值的约束，并保留最终引脚/端口检查。把实现工作移到这里，不会放宽这些义务，也不声称当前编译器已经满足它们。

### B.1 职责与实现方向

共享声明验证器是设计 §8 静态检查的拟议编译器内部实现，覆盖已提供的 fn/subdesign 定义和新循环作用域。即使定义未被使用，也检查已知的名称、种类、单位及引用/trait 约束。它不需要为抽象参数编造具体值，不分配假想电路，不替代最终组装，也不增加第五条残余 DRC。现有 `src/check/bodies.rs` 和共享泛型环境是后续原型的实现接点。

这有意**替换此前只对新循环加强检查的策略**。基线 `check/bodies.rs` 记录了未调用体中的重复局部名、抽象泛型检查等缺口。统一补齐可静态判定的重复/泛型/引用缺口，是本次提议修订的一部分，不是未披露的实现重构。兼容性成本明确：含有这类无效但过去未检查的未调用定义的旧源码，现在可能失败。需要更新偏离记录，并加入隔离的前后对照测试。不能悄然扩张为新的全局 fn 递归检查或数值证明：保留 RFC-006 的实际调用环拒绝规则；RFC-032 的递归包含仍在声明时检查，并报告完整环。

若拒绝加强检查或另行分阶段处理，正式决策必须协调该选择与设计 §8 及验收案例，必要时明确统一的替代方案。不能悄悄恢复由调用者决定检查强度。完成本次编辑不要求先完成原型；下列兼容性证据仍是接受拟议旧声明检查行为修正的条件。

### B.2 后续修订所需的证据

**接受前所需的兼容性证据：** 在同一个已记录源码版本、同一精确依赖集合下，对 `lib/` 中每个包分别运行现有检查器和提议声明验证器的原型。必须包含未使用的 fn/subdesign 定义；仅检查已实例化的板级示例，无法衡量此项变化。报告检查的包/定义数、按类别统计的新增拒绝定义及诊断（包括实测为零的情况），以及每项差异的源码位置和所需迁移。显式记录未解析依赖或跳过的定义；不能把它们计入通过覆盖。除逐项记录的新增声明错误外，保持改动前有效语料的判定与输出字节。此项语料审计尚未执行：提议验证器尚未实现。当前 `cargo test` 通过，不是这项未来兼容性成本的证据。

**准备阶段发现的覆盖情况：** `docs/reviews/evidence/2026-09-12-m2-declaration-inventory.json` 中的固定基线源码/AST 清单覆盖 60 个包和 162 个源码文件，但只有两个非泛型 fn 定义，没有 subdesign 定义。它记录解析成功及源码/manifest/锁哈希，不代表依赖验证或语义审计成功。保留全库兼容性审计，并增加单独报告的针对性语料，覆盖泛型 fn/subdesign 声明、未使用体、重复名称与合法网络续写的区别、trait/引用/端口义务和环检查阶段。缺少某类声明是覆盖缺口，不能证明其新检查保留了行为。
